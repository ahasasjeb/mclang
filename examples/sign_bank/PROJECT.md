# 告示牌账户银行

Minecraft Java Edition 26.3 / pack format 121.0。32 个独立账号，账号与密码分别存放在机房的两块告示牌；余额、尺寸、就绪状态保存在对应槽位的 marker 上。所有游戏逻辑用 MCL 结构化语法实现，严格模式为 0 条底层语句。

## 构建与安装

```powershell
cargo build --bin mclang
target/debug/mclang.exe check examples/sign_bank --deny-raw
target/debug/mclang.exe build examples/sign_bank -o build/sign_bank --deny-raw
```

将生成的整个 `build/sign_bank` 放入世界的 `datapacks`，然后执行 `/reload`。大厅位置为 `0.5 64 5.5`，面向北方（yaw=180）。超平坦地表高度不作依赖：大厅地板固定在 y=63。

首次加载会自动初始化。需要清空全部账号、余额和仓库时执行：

```mcfunction
/function sign_bank:reset
```

**reset 会清空本数据包的账号、余额和指定仓库区域内的物品/方块。** 普通 `/reload` 只注销会话、清理展示与未完成注册，不重建账号和房间。初始化等待所有目标区块加载完成后再放置方块。

## 操作

1. 首屏点击独立的登录或注册命令牌。
2. 中间输入牌的第一行填写账号；第一步只暂存文本，不占用正式槽位，也不创建半成品账号。
3. 密码提交后，在同一次函数执行中检查重复、选择槽位、写入并回读两块凭据牌，然后才扣除 1 绿宝石并提交 marker。扣费后的提交失败会自动回滚凭据并退费。
4. 仓库门厅中四块命令牌分别存入全部绿宝石、取出 1 枚、升级、安全退出。
5. 上方 text_display 显示槽位编号、余额、仓库尺寸与升级费用，满级显示已达上限。

输入按文本组件复制，不解析成数字。已验证前导零、英文、中文、字母数字混合、引号与反斜杠；`123` 和 `00123` 是不同账号。大小写与字符内容需要一致。

## 空间与数据

- 大厅/屏障机房：x=-10..10，y=63..82，z=-12..12。
- 大厅标题、输入/说明、操作按钮分别位于 y=66/65/64，输入牌与站立玩家视线基本齐平。
- 槽位 i 的房间原点：x=100+16×(i-1)，y=63，z=0。阵列终点 x=607；各房间外壳 12×8×14。
- 可用仓储区：相对 x=1..n，z=3..n+2，n=3..10；另有固定 3×2 控制门厅，不计入仓储尺寸。
- 基岩墙/地板/顶板给出实际边界；雕纹石砖地板标识可用仓储区，y=69 的 light 方块提供 15 级照明。
- 仓库控制牌位于 y=64..65；账户展示中心位于相对 marker `(-3.5,-0.5,-5.4)`，低于顶层并向门厅内侧离开基岩墙面。
- 升级仅开放新增两条边，不重填已有区域；费用等于新边长，3→10 共需 49 绿宝石。
- 常加载共 36 个区块（大厅 4 + 房间 32），只在主世界操作固定设施。
- 机房账号牌：x=-4+(i-1)%8，y=66+3×floor((i-1)/8)，z=-7；密码牌位于同列 y+1。
- scratch 的 x=5/6/7/8/9 分别为当前值、比较、空白模板、暂存账号、暂存密码，y=66，z=-7；只跨页保留 `front_text.messages[0]`。每次读取都重新套用空白模板，绝不跨 tick 比较完整告示牌 NBT。
- `sb_registering` 临时 tag 持有注册流程；正式账号槽位只在最终提交函数中分配。`sb_registration_paid` 只存在于扣费成功到 marker 提交完成之间，用于统一退款。
- marker 的固定整数槽位连接账号、密码、余额和房间，绝不根据用户名转数字或使用“最近 marker”匹配。
- 重复账号、重复 marker、无效页面、已在线账号和非独占仓库都拒绝操作。没有周期性“清理未完成正式记录”：取消注册只清空 scratch 与玩家 tag。
- text_display 带专属 `sb_display` 标签，更新前删除本槽位旧展示；退出、断线、重载、重建都清理，不影响其他实体。

## 实际 Minecraft 验收

`verification/run.ps1` 把真实 MCL 产物装入 Mojang GameTest 服务端，在 `target/sign-bank-runtime-<随机值>` 新建隔离世界。通过本机 26.3 客户端 JAR 的服务端类运行，不进入或修改玩家存档。Java 25、2 GB 堆、4 个处理器线程。

```powershell
powershell -NoProfile -File examples/sign_bank/verification/run.ps1
# 可指定安装目录与 Java 25：
# ... -Minecraft E:\mc -Java "D:\Program Files\Microsoft\jdk-25.0.3.9-hotspot\bin\java.exe"
```

2026-09-28：411 项断言通过，1 个 GameTest 场景通过。测试创建模拟玩家并调用告示牌原版点击入口，实际执行生成的 mcfunction。覆盖：

- 8 种文本账号/密码往返；32 槽注册；第 33 个在原子提交时拒绝；取消与空密码不产生半成品正式记录。
- 每次注册在账号与密码步骤之间修改暂存牌的非文本 NBT，并强制运行 25 次 tick，确认菜单维护和时间间隔不会破坏暂存文本。
- 无效暂存数据在扣费前取消；模拟已扣费事务取消时退回绿宝石并清除临时标签。
- 大厅标题高度、仓库展示高度及其与基岩墙面的距离均有几何断言。
- 重复账号、重复槽位、其他账户密码的拒绝；清理不误删正式凭据。
- 真实绿宝石扣费、存取款、独立余额；展示内容解析与去重。
- 每级 3×3→10×10 的基岩边界与 light 顶层；带 7 枚钻石的箱子内容保持不变。
- 双人登录区限制、仓库闯入立即阻止扣款并双人退出、相邻房间独立运行。
- 退出、断线与 load 流程清理展示，会话失效后账号/余额/箱子保留。

运行器还检查日志中的方块实体解码错误，避免断言通过却仍有无效命令牌。头部 JVM 的第三方 Unsafe 提示与数据包无关。

## 语言支持结论

已实际覆盖模块导入/上下文校验、score 参数与返回值、短路条件、unroll 坐标展开、结构化 execute/store、NBT 复制、clone/blocks 比较、实体查询、召唤与移除、计分文本、fill 筛选、跨维度和 schedule。

全部 7 个模块经 CLI 翻译为中文后再次严格编译，680 个产物文件与英文版本逐字节一致。最终函数引用无缺失，所有 `if blocks` 均显式包含比较模式。

发现的边界：

- MCL 尚未检查告示牌 NBT 字段对应的完整 codec：`front_text.color` 必须是染料色（如 cyan），内层文本 `color` 是聊天色（如 aqua）。此前错误把两者混用，Minecraft 日志会报错；示例已修正。
- 普通参数是 score，不可用来保存账号字符串；本例通过 NBT 原样复制。
- `~(编译期表达式)` 尚不支持，本例用 `unroll for` 计算绝对坐标。没有引入运行期字符串宏或原生命令逃生口。

文件职责：`main.mcl` 管生命周期，`ui.mcl` 管菜单，`auth.mcl` 管认证流程，`accounts.mcl` 管双牌存储，`rooms.mcl` 管几何与独占检查，`bank.mcl` 管收支，`displays.mcl` 管展示清理。
