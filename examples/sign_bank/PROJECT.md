# 告示牌账户银行

这是一个面向 Minecraft Java Edition 26.3 的 Mclang 压力测试数据包。它在超平坦世界上方自动建立登录墙、受屏障保护的告示牌“服务器”阵列，以及 32 间独立的实体仓库。

## 构建与安装

在仓库根目录执行：

```powershell
target/release/mclang.exe check examples/sign_bank --deny-raw
target/release/mclang.exe build examples/sign_bank -o build/sign_bank --deny-raw
```

把 `build/sign_bank` 复制到世界的 `datapacks` 目录并执行 `/reload`。大厅中心在 `(0.5, 64, 5.5)`；若玩家没有出生在那里，可先用管理员命令传送过去。

首次加载会改写以下无人使用区域：

- 大厅与机房：`x=-10..10, y=63..82, z=-12..12`
- 仓库阵列：`x=100..545, y=63..70, z=0..13`

`installed` 标志会阻止 `/reload` 再次搭建这些区域，因此重载不会清空注册资料、箱子或玩家放置的方块。

## 使用方法

1. 准备至少 1 枚绿宝石。
2. 到达登录墙后先看到紧凑的三层告示牌首屏：上方是页面状态，中间牌此时锁定，下方左右各有一块独立命令木牌，分别用于“登录账户”和“注册账户”。
3. 选择功能后进入对应的账号页，中央牌才变成可编辑状态。只在第 1 行填写账号，然后点击“提交当前输入”。
4. 只有账号存在或允许注册时，菜单才会切换到对应的密码页，并立即擦除账号输入。再次编辑中间牌，只在第 1 行填写密码，再次提交。
5. 登录账号、登录密码、注册账号和注册密码都是独立页面。任一子页面都可以点击“返回首屏”；离开登录区、第二名玩家进入或断线也会自动返回首屏，注册流程占用的临时槽位会被释放。
6. 注册成功后自动进入专属仓库。北墙命令牌可存入背包内全部绿宝石、取出 1 枚、升级仓库或安全退出。
7. 仓储区初始为 3×3，最大为 10×10。升级费用依次为 4、5、6、7、8、9、10 枚绿宝石，总计 49 枚。

## 实现结构

登录墙本身是一套物理告示牌菜单，最高只到 `y=67`：状态屏位于 `y=67`，中央输入区位于 `y=66`，两块独立命令木牌位于 `y=65`。每块命令牌只包含一个点击事件并只执行一个动作。`auth_mode` 的五个值分别表示首屏、登录账号、登录密码、注册账号和注册密码；登录区强制单人，因此数据包可以按当前玩家状态安全切页。首屏中央牌带蜡、不可编辑；只有进入子页面后才换成空白可编辑牌。

Minecraft 26.3 的 `SignBlockEntity` 把“上蜡”和“允许高权限特性”分成了两个 NBT 开关。命令牌必须同时设置 `is_waxed = true` 和 `allow_op_features = true`；只有前者时，原版会识别到点击事件但拒绝执行，并显示“此告示牌的点击操作已被禁用”。此外，原版点击一块牌时会遍历四行并执行每个点击事件，不会按玩家点中的文字行选择动作。因此首屏按钮、提交/返回按钮以及仓库的存入、取出、升级、退出均使用独立木牌，每块牌只含一个 `run_command`。

这些 `run_command` 直接调用导出的 `@player` Mclang 函数。四个认证页面各有专属入口，例如注册账号页执行 `/function sign_bank:button_register_account`，不再读取 `auth_mode` 后二次分发；仓库存款牌则执行 `/function sign_bank:rooms/button_deposit`。这样点击在同一游戏刻得到声音和 actionbar 状态，不依赖 `/trigger` 的启用、锁定与下一刻轮询；导出函数仍会检查菜单状态、登录区人数或仓库会话。

认证过程没有把密码转换成程序字符串。账号页只复制输入牌第 1 行，并与 32 块账号索引牌逐槽比较；匹配后用玩家的 `auth_mode` 和 `pending_slot` 记录“正在等待哪个账户的密码”。密码页重新读取已经擦除过的输入牌第 1 行，在机房内组装临时凭据牌，再用原版 `execute if blocks` 与对应凭据牌比较。账号和密码从未同时出现在公开输入牌上。

注册也采用相同的两阶段协议。账号通过检查后，该槽位暂记为 `-1` 并保存账号索引；只有密码非空且实际扣除注册绿宝石后才转为正式账户。认证被中断时，预留槽位和临时索引都会清除。

账户的绿宝石余额和仓库边长由全局计分状态持久化，账户当前会话由玩家计分记录。物品和方块不做 NBT 序列化：它们始终留在对应的实体仓库里。升级只把尚未开放的屏障外圈替换为空气，不会重填已经开放的区域，因此旧箱子和方块不受影响。

登录区的坐标盒同时出现两名玩家时，注册和登录按钮都会失效。每间仓库也有独立坐标盒：检测到第二人会注销房内所有会话；无正确会话的闯入者、离开所属仓库的玩家和断线重连者都会被送回大厅。

## 边界与安全说明

- 这是对原版数据包和 Mclang 表达能力的测试，不是密码学系统。密码以明文文本组件保存在世界中的告示牌 NBT；服务器管理员、拥有命令权限的人和能读取存档的人都能查看。
- 容量固定为 32 个账户。固定容量换来了完全类型化、可用 `--deny-raw` 验证的实现，并避免运行期宏坐标注入。
- 槽位表与房间网格改用编译期循环 `unroll for`：索引在循环体内是编译期常量，坐标由索引算出（如 `pos(-4 + (index - 1) % 8, 74 + 2 * ((index - 1) / 8), -7)`），因此产物仍是每槽位一条静态命令，没有循环假玩家与循环辅助函数；索引来自运行期值时只保留一条 `if index == slot` 守卫，复杂度仍是 O(32)，不会退化成 O(1024)。`enter_account` 的落点是小数坐标，小数分量只接受字面量，因此那里保留显式展开。
- 数据包常加载从 `(-16,-16)` 到 `(559,15)` 覆盖的 72 个区块，用于让大厅、机房和全部仓库持续可见。它低于原版 256 个强制加载区块上限，但不适合与大量其他常加载设施重叠部署。
- 仓库控制牌所在格是保留位置，每秒会自动修复；不要把方块放在该格。其余已开放仓储区不会被维护逻辑改写。
- 管理员删除计分板目标、手工改动记录牌、执行 `forceload remove all` 或删除数据包都属于外部破坏，不提供自动恢复。
