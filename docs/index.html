认识 Mclang

手写 .mcfunction 时，一个“每五秒给所有玩家发一次奖励”就需要同时处理计分板假玩家、execute as执行 作为/at 上下文、函数标签、tellraw 的 JSON 和 give给予 的物品组件语法。Mclang 把源码分成了明确的层：

  • 声明层：namespace命名空间、score计分、objective目标、query查询、item物品、storage存储、data_slot数据槽、resource资源、fn_tag函数标签、fn函数，编译器检查重名、类型与资源位置。
  • 语句层：execute执行、each遍历、spawn召唤、give给予、self.*自身.*、message.*消息.*、title.*屏幕标题.*、bossbar.*Boss栏.*、dialog.*对话框.*、particle粒子、stopsound停止声音、posteffect.*后处理效果.*、effect.*效果.*、xp.*经验.*、scoreboard.*计分板.*、teleport传送、schedule调度、if如果/while当 以及 set_block设置方块、fill填充、clone复制 等世界命令，每条都有结构化 AST 表示。
  • 表达式层：整数、计分值、带返回值的函数调用与 scoreboard.get计分板.取、xp.query经验.查询、stopwatch.query秒表.查询、time.query时间.查询、gamerule.query游戏规则.查询、worldborder.get世界边界.获取 等查询表达式。
  • 底层逃生口与严格模式：run原生命令、字符串形式的 execute执行 与 return run返回 原生命令 接受原生命令文本。--deny-raw 会拒绝这些写法，也会拒绝运行期 with用 宏调用和声明 nbt数据 参数的宏函数。

输出结构

每次构建都会重写 .mclang-manifest，下一次构建先删除上次清单里的文件再写新文件；清单损坏、含绝对路径或 .. 时构建直接失败，目录里的其他文件不会被碰。写完新文件后，编译器会回收 data/数据操作/ 下不再包含文件的空目录，因此函数改名或模块删除不会在产物里留下空文件夹。

编辑器支持

仓库自带 VSCode 插件（editors/vscode）与语言服务器（mclang lsp）。插件提供中英文关键词语法高亮、与命令行同一套即时诊断、补全、悬停说明和跨文件跳转；可执行文件会在工作区 target/release、target/debug 与 PATH 中自动查找，也可以用 mclang.server.path 指定。

语言基础

注释、字符串与数字

  • 注释：// 到行尾，没有块注释。
  • 字符串：双引号，支持转义 \"、\\、\n、\r、\t，不能跨行。
  • 原始字符串：""" 到下一个 """，可以跨行，内容不做转义——适合内嵌 JSON。
  • 数字：十进制整数（32 位范围内）与小数（1.5、0.25）；NBT 的类型后缀见结构化 NBT。
  • 标识符：字母、数字与下划线，不能以数字开头。ASCII 名必须是小写字母、数字与下划线，不超过 32 个字符，且不能是保留字（中英文关键词都是保留字）。中文等非 ASCII 字母也允许，编译时会被换成随机 ASCII 别名，见中文标识符。

程序结构与模块

项目是一个目录，入口模块固定叫 main.mcl：mclang build <目录> 从入口出发，沿 import导入 边加载其他 .mcl 模块；入口到不了的 .mcl 文件不参与编译（入口只 import 一次就够，即使不引用它的名字，模块里的进度、函数标签等资源也会生效）。

  • 每个 .mcl 文件是一个模块，模块路径是它相对项目根目录的路径：lib/math.mcl 与 lib/math/mod.mcl 都是 lib/math，入口自身是空路径。
  • 入口必须声明 namespace <名称>;命名空间 <名称>;；其他模块可以省略（继承入口），写了则必须与入口一致。命名空间只能包含小写 ASCII 字母、数字与下划线，不能以数字开头，也不能是 Windows 保留设备名。
  • 顶层声明默认私有；export公开 之后才能被其他模块导入，导入方必须写 import导入。声明顺序不影响引用，导入环是允许的。

单文件输入（mclang build examples/counter.mcl）等价于只有一个入口模块的项目，不需要 main.mcl，也不需要任何 import导入。

模块与导入

import导入 的路径始终相对项目根目录，a::b 对应 a/b.mcl 或 a/b/mod.mcl；入口模块也可以用 import main; 被其他模块导入，因此入口与子模块可以互相引用。可见性规则：

  • 模块自己的声明始终可见；导入进来的名字与局部声明重名时，局部声明优先。
  • 两个模块整模块导入时导出同名声明会报错，改用选择性导入或 as作为 别名。
  • 选择性导入不存在的名字、导入没有 export公开 的名字、模块文件缺失都会在编译期报错并给出位置。

命名规则：函数、JSON 资源、进度与函数标签的限定名用 / 连接（例如 lib/math 里的 sum 是 lib/math/sum），因此产物直接落在 data/<命名空间>/function/lib/math/sum.mcfunction、predicate/lib/strings/on_fire.json；计分变量、目标、查询、物品、存储与数据槽的名字用 . 连接（例如 lib.state.total），因为计分板假玩家和目标名不能包含 /。入口模块的名字保持原样。

examples/module_demo 由文档构建与回归测试实际编译：sum 的产物是 data/module_demo/function/lib/math/sum.mcfunction，函数在数据包里的名字就是 module_demo:lib/math/sum；__mcl 下的辅助函数同样带模块路径，例如 __mcl/lib/math/sum/0。

内置标准库

标准库随编译器提供，项目里无需复制库文件。用普通 import std::模块::{函数, ...}; 显式导入；只会把入口可达的模块加入数据包，导入一个模块会生成该模块的全部公开函数，但不会自动注册 @load@加载 或 @tick@每刻。std 路径保留给内置模块，项目不能用自己的 std/ 文件覆盖它。函数名和模块名是 API 标识符，不随中英文关键词切换。

模块导出函数典型用途
std::mathabs、min、max、clamp、sign限制计分范围、处理伤害和方向
std::statenormalize、toggle、latch、rising_edge、falling_edge开关、一次性触发与状态变化检测
std::timeseconds_to_ticks、ticks_to_seconds、interval_due、cooldown_ready、remaining周期任务、冷却与倒计时
std::randomchance、chance_per_mille按百分比或千分比触发事件

所有函数使用 32 位计分整数。布尔函数把 0 视为假、其他值视为真，并返回 0 或 1；rising_edge 和 falling_edge 的调用方需要保存上一刻的状态。时间函数使用每秒 20 刻的换算，interval_due 的周期必须大于 0，调用方在触发后更新 last_tick。chance 接受 0–100，chance_per_mille 接受 0–1000，超出范围时分别按 0 或必定触发处理。clamp 的下界高于上界时返回下界。计分运算仍遵循原版 32 位行为，调用方应避免乘法及时间差溢出。

中文标识符

计分变量、函数、查询、物品、存储、数据槽、目标、谓词资源、进度、函数标签、参数与局部变量的名字可以直接写中文。编译时（语义检查之后、生成数据包之前）这些非 ASCII 名字会被替换成随机 ASCII 别名：别名由名字的稳定哈希驱动，同一份源码总是得到同样的 8 个小写字母；每个别名在整个项目里唯一，并自动避开已有的 ASCII 标识符，所以不会与现有变量冲突。引用与声明走同一张映射表，诊断信息仍使用源码里的名字。

结构化 NBT（nbt）

nbt { 键 = 值; }（中文 数据 { 键 = 值; }）是一段结构化 NBT 数据，覆盖 26.3 SNBT 的全部 12 种标签类型。键写成标识符或字符串，每个条目以 ; 结束；值的形式如下：

写法NBT 标签说明
1b / -2BTAG_Byte后缀 b，范围 -128 到 127
1sTAG_Short后缀 s，范围 -32768 到 32767
1 / 1iTAG_Int无后缀或 i，32 位范围
1LTAG_Long后缀 L，64 位范围
1.5f / 1fTAG_Float后缀 f，必须能表示为单精度
1.5 / 1.5d / 1dTAG_Double无后缀小数或 d
"文本"TAG_String必须加引号；true真/false假（true真/false假）按 SNBT 规则是字节 1/0
[值, 值]TAG_List元素类型可以不同，允许空列表
{ 键 = 值; }TAG_Compound可以嵌套
[B; 1b, 2b]TAG_Byte_Array元素用 b 后缀或无后缀整数
[I; 1, 2]TAG_Int_Array元素可用 b/s/i 后缀
[L; 1L, 2L]TAG_Long_Array元素可用 b/s/i/L 后缀

后缀大小写皆可（1b 与 1B 等价，数组前缀 B/I/L 只接受大写）。编译期检查数值范围、单精度可表示性、数组元素后缀与数组类型是否匹配、复合键是否重复；输出按 26.3 的规范化写法生成（1b、1s、1L、1.5f、1.5d、[B;1B] 等）。

nbt数据 可以用在需要 NBT 的位置：set_block设置方块/fill填充 的方块实体数据、物品定义的 custom_data 组件，以及作为语句合并到当前实体（见实体 NBT）。它不能在运行时拼装——形状在编译期就是确定的。

顶层声明

计分变量（score）

声明一个全局计分变量并给出初始值（32 位有符号整数，可带负号）。变量保存在计分板假玩家 #v_<name> 上，随世界存档持久化；/reload/重载 只会在缺少时补写初始值，不会把已有值重置。

实体查询（query）

查询是一段可复用的选择器。entity(...)实体(...) 已指定正向实体类型，因此 type(...)实体类型(...) 会报互斥诊断。原版只允许在正向 #类型标签 后继续追加排除条件，所以 without_type(...)排除类型(...) 仅能用于 entity("#标签")实体("#标签") 查询；具体实体类型后再写会在编译期拒绝。tag标签、without_tag、without_type 和 scores 可以重复（同一个类型标签或计分目标不能重复），多个分数条件会合并为一个 scores={...}分数={...} 选项；其余属性各只能出现一次。distance 与 within 会合并成同一个区间，交集为空时报错。区间不接受倒置边界或非有限小数；distance 和 level 的边界不能为负，整数边界必须落在 32 位整数范围。team队伍 只接受不含空格的命令单词。nbt数据 需要完整的 SNBT 复合标签；advancements 使用进度 ID 与 true真/false假，可嵌套准则过滤。level、gamemode游戏模式 仅适用于玩家查询。item物品 过滤器的槽位是原版槽位名（contents内容、weapon.mainhand、armor.*、container.0 …）或 slot_source 资源位置，id 可以是物品 id、#标签 或带 [组件过滤器] 的谓词。查询不产生命令，只在 each遍历、give给予、effect效果、xp经验、clear清除、count计数 与条件里被引用。

控制流（if / else / while / for）

if如果 与 while当 保持当前执行上下文，不引入新实体。简单条件可以直接生成原版 execute if/unless执行 如果/除非；需要保存求值结果时，条件会生成 0/1 的临时计分项，再用 matches 1匹配 1 或 matches 0匹配 0 选择分支。带 else否则 的条件只求值一次，执行真分支后不会重新判断条件。

编译期能确定的条件会被折叠：if 1 == 1如果 1 == 1 直接把真分支展开进当前函数（不生成标志，也不分配辅助函数），if 2 < 1如果 2 < 1 整段省略（else否则 分支同理）；while 0 == 1当 0 == 1 不生成任何循环命令。

&&、|| 从左到右短路。右侧即使是恒假或恒真条件，也不会删除必须执行的左侧调用，例如 side_effect() == 1 && 0 == 1 仍然执行一次 side_effect()。

for对于 是半开区间循环，起止都可以是表达式：常量终点直接生成 matches ..<终点-1> 比较，动态终点只求值一次并存入循环上限计分项；常量空区间（起点 ≥ 终点）不生成命令。循环变量是循环体内的局部计分项，兄弟循环可以复用同一个名字，但不能与参数、let令 或全局计分变量重名。

break跳出 与 continue跳过 只允许出现在 for对于/while当 里：each遍历、spawn召唤 的每个实体会单独执行，不能用它跳出。需要跳转的循环有一个状态计分项（1 = continue，2 = break）：循环体里设置的循环状态在其所在辅助函数返回后立即生效，最多跳出一层循环；嵌套循环独立处理自己的跳转，无跳转的外层循环不会因此分配状态计分项。

return返回 只能直接出现在函数最外层代码块，不能放进 if如果、while当、for对于、each遍历、spawn召唤、in_dimension在维度 或 execute执行 块——这些结构会展开成辅助函数，块里的 return返回 只会结束辅助函数。需要条件结果时先给局部变量赋值，在函数末尾统一 return返回；结构化 execute执行 的 store 子句则直接捕获块内最后一条命令的结果（见结构化执行）。

while当 的每轮迭代都会重新求值条件：循环辅助函数先算条件，命中就调用循环体辅助函数，再按循环状态处理 break跳出/continue跳过 并递归下一轮，运行时上限由 Minecraft 的命令链长度决定；请确保每次迭代都会改变条件里的计分变量，或使用 break跳出 退出。

let令 声明只在函数（块）内可见的局部变量，作用域不能遮蔽全局计分变量或参数。除零在编译期直接拒绝（右操作数是常量 0 时）。

语义要点：

  • store 捕获的是块内最后一条命令在修饰符上下文里的结果；条件不成立时块体不运行，store 不写入。
  • 末尾的计分赋值保留可观察的赋值结果，包括 counter = counter、counter = counter + 0 等自赋值；不会因消除赋值而错误捕获前一条命令或右侧调用的结果。
  • 最后一条语句是 if如果、while当、each遍历、spawn召唤、in_dimension在维度 或 execute执行 等控制结构时结果不会传递，编译器直接拒绝；调用带 -> score-> 计分 返回值的函数可以，此时捕获的是函数的返回值。
  • 计分板持有者支持 self自身/自身、origin投掷者/投掷者 与实体查询（查询生成计分板选择器，可一次写入多个实体）。投掷者目标会拆成「先捕获到临时计分项，再用 on origin 复制」：命令没有执行时（例如查询没有命中）目标保持原样，与原版 store 的触发条件一致。
  • store.data存值.数据 的实体来源需要 limit(1)上限(1) 查询；self自身 要求非玩家上下文，查询来源会检查实体类型，origin投掷者 无法静态确认，投掷者恰好是玩家时 Minecraft 拒绝写入。
  • Boss 栏必须在运行期已经存在（由 /bossbar add/Boss栏 添加 或后续的 bossbar 命令族创建），否则整条命令失败、不写入。
  • 没有命中实体、命令失败或条件不成立时 Minecraft 可能完全不写入，这与原版 execute store执行 存值 一致；读取时先按 0 处理。

条件与投掷者 store.result 的实际产物：带条件的块直接串入原版 execute；投掷者目标仍在辅助函数里先捕获，再复制回原执行来源。

常见问题

为什么 return返回 不能写在 if如果 里？

Minecraft 的 return返回 只结束当前 .mcfunction。Mclang 的 if如果、while当、each遍历 等结构会展开成辅助函数，块里的 return返回 只会结束辅助函数，与作者预期不符。需要条件返回值时，先给局部变量赋值，在函数最外层末尾统一 return返回。

为什么带参数的函数不能直接 schedule调度 或被原版 /function/函数条件 调用？

参数保存在函数私有的固定计分项里，调用方负责写值。schedule调度 发生在未来的游戏刻，原版 /function/函数条件 也不会绑定参数，所以两者都只能看到上次留下的值。需要延时触发的参数化逻辑，请包一层无参数函数，由它写参数后调用真正的函数。

/reload/重载 会重置计分变量、存储和秒表吗？

不会。计分板、storage存储 与秒表都属于世界存档数据。__mcl/load 只创建缺失的 objective、给缺失的计分变量补初始值、把 item_list物品列表 存储补成空列表；已有值保持原样。需要每次加载都重置的状态请显式赋值。

中文声明名会变成什么？

数据包最终落在文件系统上，函数名与文件名一一对应，所以中文（或其他非 ASCII）声明名在语义检查之后会被换成随机 ASCII 别名。别名由名字的稳定哈希产生——同样的源码总是得到同样的别名——并且在整程序范围内唯一、自动避开已有的 ASCII 标识符，不会与现有变量冲突；ASCII 声明名保持原样，命名空间仍只接受小写 ASCII。函数名与命名空间还会拒绝 Windows 保留设备名（CON、NUL、COM1 等），资源路径的每个文件名段同样受限，保证产物在常见平台上都能落地。

while当 会一直循环到什么时候？

while当 的循环体和条件互相调用，每轮消耗命令链预算。请在循环体里修改条件涉及的计分变量；如果条件永远成立，最终会撞上 Minecraft 的命令链长度限制。

两种关键词写法的产物真的一样吗？

是的。构建脚本会把文档里的每个完整示例翻译成英文与中文两版，分别用编译器构建，并逐文件比较字节；以 --self-test--自身-测试命令 运行时，仓库 examples/ 下的全部示例也会做同样的往返验证。任何翻译或实现偏差都会让构建失败。

函数宏与原生参数来源

macro fn宏 函数 的参数按 类型 名称 声明，类型为 integer整数、decimal小数、text文本、resource资源、nbt数据。宏参数不是计分变量，不能与普通计分参数混合。文本和 NBT 字符串中的 $(名称) 会生成原版宏占位符；坐标或朝向分量写成 macro(名称)，要求整数或小数类型，方块坐标要求整数。宏不能作为 @load/@tick@加载/@每刻 入口，也不能声明 -> score-> 计分。

字面量调用检查必需键、参数类型和已知坐标范围；额外键遵循原版规则忽略。每个占位符必须有声明，每个宏参数必须被使用。text文本 参数禁止引号、反斜杠、控制字符和二次占位符，避免破坏生成的字符串。宏参数键保留原名，模块函数名仍按语言规则重写；嵌套的条件、循环和执行块会自动转发宏参数。

运行期来源使用以下形式，末尾路径可省略。来源必须在运行时提供复合标签；实体来源要求单实体，允许读取玩家数据。

with用 来源不能在编译时验证实际键和值，因此计入 --deny-raw。nbt数据 类型用于 run原生命令 模板中的完整 SNBT 片段，也计入不安全宏；资源 id 等未建模动态位置可通过 run原生命令 模板表达。普通 call f(...)、表达式调用、无参数标签调用和 schedule调度 不能调用需要宏参数的函数；标签宏调用会逐个检查本地成员的参数和执行上下文。schedule.clear调度.清除 只能清除函数，原版不接受 #标签。
