Mclang 是一门面向 Minecraft Java Edition 26.3-rc-2 的数据包编程语言。作者用命名、类型和结构化语法描述实体查询、物品、消息、控制流与世界命令，实体选择器、execute 上下文、NBT 路径、文本组件 JSON、计分板 ABI 与数据包目录全部由编译器生成并检查。

本手册怎么读

语法模板里的尖括号是占位符，例如 give(<players>, <stack>)给予(<players>, <stack>)；标注“编译器验证通过”的完整示例由 docs/tools/build.mjs 分别用英文与中文关键词编译过，两种写法的数据包逐字节一致，示例里的 .mcfunction 片段是编译器实际产物。顶栏的 “English keywords / 中文关键词” 按钮会把页面上的 Mclang 代码块、行内关键词、方法名与枚举值整体切换；只翻译关键词，注释、字符串与标识符保持原样；生成的命令与目录树不参与切换。

认识 Mclang

手写 .mcfunction 时，一个“每五秒给所有玩家发一次奖励”就需要同时处理计分板假玩家、execute as/at 上下文、函数标签、tellraw 的 JSON 和 give给予 的物品组件语法。Mclang 把源码分成了明确的层：

  • 声明层：namespace命名空间、score计分、query查询、item物品、storage存储、resource资源、fn_tag函数标签、fn函数，编译器检查重名、类型与资源位置。
  • 语句层：each遍历、spawn召唤、give给予、self.*自身.*、message.*消息.*、effect.*效果.*、xp.*经验.*、schedule调度、if如果/while当 以及 set_block设置方块、fill填充、clone复制 等世界命令，每条都是独立 AST 节点。
  • 表达式层：整数、计分值、带返回值的函数调用与 xp.query经验.查询、stopwatch.query秒表.查询、time.query时间.查询、gamerule.query游戏规则.查询、worldborder.get 等查询表达式。
  • 逃生口：run原生命令 与 execute原生执行 接受原生命令字符串，--deny-raw 可以强制项目完全停留在标准层。

中英关键词完全等价

每个关键词、函数属性、方法和枚举值都有英文与中文写法，两种写法可以在同一个文件、同一条语句里混用。编译器保证两种写法生成逐字节相同的数据包；本手册的构建脚本会在每次生成时重新验证这一点。

命令行

命令作用
mclang check <输入>只做检查、不写文件，全部诊断一次返回，通过后打印资源统计
mclang build <输入> [-o 目录]通过全部检查后写出数据包，默认输出到 build/<名字>
--deny-raw严格模式：项目里出现任何 run原生命令、字符串 execute原生执行 或 return run返回 原生命令 就拒绝构建
--description <文本>写入 pack.mcmeta 的描述，默认 Generated by mclang
mclang lsp在标准输入输出上启动语言服务器，供编辑器插件使用

输入可以是单个 .mcl 文件，也可以是递归包含 .mcl 的目录；同一个项目里的所有文件必须声明相同命名空间，声明与引用在整个项目内可见。

把输出目录复制到世界的 datapacks/ 下，执行 /reload 即可。数据包格式固定为 121.0。

输出结构

每次构建都会重写 .mclang-manifest，下一次构建先删除上次清单里的文件再写新文件；清单损坏、含绝对路径或 .. 时构建直接失败，目录里的其他文件不会被碰。

编辑器支持

仓库自带 VSCode 插件（editors/vscode）与语言服务器（mclang lsp）。插件提供中英文关键词语法高亮、与命令行同一套即时诊断、补全、悬停说明和跨文件跳转；可执行文件会在工作区 target/release、target/debug 与 PATH 中自动查找，也可以用 mclang.server.path 指定。

语言基础

注释、字符串与数字

  • 注释：// 到行尾，没有块注释。
  • 字符串：双引号，支持转义 \"、\\、\n、\r、\t，不能跨行。
  • 原始字符串：""" 到下一个 """，可以跨行，内容不做转义——适合内嵌 JSON。
  • 数字：十进制整数（32 位范围内）与小数（1.5、0.25）。
  • 标识符：字母、数字与下划线，不能以数字开头。声明名（函数、计分变量、查询、物品、存储、函数标签、参数与局部变量）必须是小写 ASCII 字母、数字与下划线，不超过 32 字节，且不能是保留字。

程序结构与命名空间

每个文件都以 namespace <名称>;命名空间 <名称>; 开头。项目里所有文件必须声明同一个命名空间；命名空间只能包含小写 ASCII 字母、数字与下划线，不能以数字开头，也不能是 Windows 保留设备名。声明顺序不影响引用。

执行上下文

Mclang 用四种上下文描述“这段代码在谁身上执行”，编译器据此拒绝错误的实体操作：

上下文来源含义
无@load@加载、@tick@每刻 入口函数没有执行实体，@s 不可用
任意实体@entity@实体 函数有实体，但可能是玩家
非玩家实体非玩家查询的 each遍历、spawn召唤 块、@non_player@非玩家 函数确定不是玩家
玩家玩家查询的 each遍历、@player@玩家 函数确定是玩家

非玩家实体与玩家都是“任意实体”的特例，但互不包含：Minecraft 拒绝 data ... entity 修改玩家数据，所以 self.save_items 这类 NBT 操作只允许非玩家实体上下文；玩家专用操作（message.self消息.自身、self.give_item、xp.*经验.*）反过来只允许玩家上下文。

顶层声明

计分变量（score）

声明一个全局计分变量并给出初始值（32 位有符号整数，可带负号）。变量保存在计分板假玩家 #v_<name> 上，随世界存档持久化；/reload 只会在缺少时补写初始值，不会把已有值重置。

实体查询（query）

查询是一段可复用的选择器。limit、within、sort、item物品 各只能出现一次；item物品 过滤器里的 id 必填，槽位目前只支持 contents内容。查询不产生命令，只在 each遍历、give给予、effect效果、xp经验、clear清除 里被引用。

each(q) 对玩家查询生成 execute as @e[type=minecraft:player,…] at @s …，对非玩家查询则在选择器之后追加 if items … 谓词。

物品定义（item / item_stack）

物品定义是一段可复用的物品组件文本。count 默认 1；lore、enchantment、stored_enchantment 可以写多行；组件输出顺序固定，与声明顺序无关。max_stack_size 大于 1 时不能再声明 max_damage。give给予 的数量上限是 max_stack_size × 100（未声明最大堆叠数时按 1 计算，因此上限 100）。

物品列表存储（storage）

存储是 self.save_items/self.restore_items 使用的容器位置。__mcl/load 会在首次加载时把路径初始化为空列表，/reload 不会清空已有内容。

JSON 资源（resource）

声明一份原样写出的 JSON 资源，编译后保存到 data/<命名空间>/<类型>/<名称>.json。可用的类型是 26.3 的资源目录名（见附录 C），其中 predicate谓词 可以在条件里用 if predicate(<name>)如果 谓词(<name>) 引用；其他类型写英文名称，带斜杠的类型要写成字符串名称（例如 "worldgen/feature/example"）。JSON 会在编译期解析，格式错误直接报告行列位置，输出时统一重排为两空格缩进。

函数标签（fn_tag）

函数标签输出到 data/<命名空间>/tags/function/<名称>.json，供 call #标签() 与 schedule #标签() after … 使用。replace替换 为真时写出 "replace": true"replace": 真，覆盖同名低优先级标签；默认是假，即与低优先级数据包合并。标签引用的本命名空间函数与标签必须存在，循环引用会被拒绝；字符串形式的外部引用只校验资源位置。调用标签时编译器会展开标签里的全部函数，检查它们的参数与上下文要求。

函数与属性（fn）

函数可以带任意多个参数，可以声明返回一个计分值（-> score-> 计分）。返回值有两种形式：表达式（写进临时计分项后 return run scoreboard players get …）或 return run "<命令>"返回 原生命令 "<命令>"。带返回值的函数必须以 return返回 结束。

属性含义限制
@load@加载服务器加载//reload 时运行不能带参数、不能返回值，不能与实体属性同用
@tick@每刻每游戏刻运行同上；tick.json 的顺序与源码一致
@entity@实体要求任意实体上下文与 @load@加载/@tick@每刻 互斥
@non_player@非玩家要求非玩家实体上下文与另外两个实体属性互斥
@player@玩家要求玩家上下文与另外两个实体属性互斥

参数保存在函数私有的固定计分项 #p_<哈希> 里，调用方负责写值；从 Minecraft 直接调用参数化函数不会重新绑定参数，会沿用上次留下的值，所以参数化函数只应从 Mclang 调用。参数名不能与全局计分变量重名，函数内也不能重复声明。

语句参考

控制流（if / else / while）

if如果 与 while当 保持当前执行上下文，不引入新实体。编译时条件会求值为 0/1 的临时计分项：if如果 生成 execute if score <flag> matches 1 run function <辅助函数>，else否则 分支用 matches 0；条件里的 &&、||、、比较与 predicate(…)谓词(…) 也都会下降成计分板操作。

return返回 只能直接出现在函数最外层代码块，不能放进 if如果、while当、each遍历、spawn召唤、in_dimension在维度 或 execute原生执行 块——这些结构会展开成辅助函数，块里的 return返回 只会结束辅助函数。需要条件结果时先给局部变量赋值，在函数末尾统一 return返回。

while当 的循环体与条件互相调度，运行时上限由 Minecraft 的命令链长度决定；请确保每次迭代都会改变条件里的计分变量。

let令 声明只在函数（块）内可见的局部变量，作用域不能遮蔽全局计分变量或参数。除零在编译期直接拒绝（右操作数是常量 0 时）。

遍历实体（each）

对查询结果逐个执行块内语句，并建立新的执行上下文：玩家查询进入玩家上下文，其他类型进入非玩家实体上下文。块会展开成辅助函数，生成 execute <选择器> run function <命名空间>:__mcl/<函数>/<n>。

生成实体（spawn）

在当前执行位置生成实体，块内的 self自身 指向新实体，总是进入非玩家实体上下文。minecraft:player 与 minecraft:fishing_bobber 在 26.3 中标记为不可召唤，编译器直接拒绝。生成 execute summon <类型> run function <辅助函数>。

维度上下文（in_dimension）

块内语句在指定维度执行，执行上下文保持不变。生成 execute in <维度> run function <辅助函数>。

原生执行子句（execute）

块内语句在一个额外的原版 execute原生执行 上下文中运行，子句字符串只写参数部分，例如 "as @a at @s" 或 "positioned ~ ~ ~ facing entity @s"。字符串不能为空、不能跨行、不能以 execute 原生执行 或 run 原生命令 开头、也不能以 run 原生命令 结尾；execute原生执行 语句计入 --deny-raw。

函数调用（call）

调用会先从左到右求值实参、写入被调用函数的参数计分项，再执行 function <命名空间>:<函数>。实参个数、执行上下文要求不符会编译报错；函数标签不能传参，标签里任何需要参数或上下文的函数都会让调用点报错。

调度（schedule）

after延后 接受“数字 + 单位”：t（游戏刻）、s（秒）、d（天），可带小数，例如 after 2.5 s延后 2.5 秒；换算按原版 TimeArgument 四舍五入。模式默认 replace替换，append追加 追加一次调度。被调度的函数与标签成员必须无参数、无执行上下文要求——调度发生在未来的游戏刻，不会保留实体或玩家。schedule.clear调度.清除 取消尚未执行的同名调度，只接受函数、不接受标签。

消息（message）

分别生成 tellraw @a、tellraw @s、tellraw @a[sort=nearest,limit=1,distance=..<距离>] 加文本组件 JSON。文本里的引号与反斜杠会自动转义。message.self消息.自身 要求玩家上下文；message.nearest消息.最近 的距离必须在 1 到 30000000 之间。

声音（sound.self）

在当前实体位置播放声音，生成 playsound <声音> <分类> @s ~ ~ ~ 1 1。要求玩家执行上下文；声音分类见附录 B。

状态效果（effect）

对查询中的每个实体执行 effect give @s <效果> <时长> [等级] [true] 或 effect clear @s。持续时间是 1 到 1000000 的整数秒，give_infinite 生成原版的 infinite；等级是 0 到 255，0 且不隐藏粒子时会省略这两个可选参数。

经验（xp）

xp.add 允许负数，xp.set 不允许。查询必须是玩家查询，xp.query经验.查询 还要求 limit(1)上限(1)；查询结果存放在临时计分项里，读取失败时为 0。

清空物品（clear）

生成 execute <选择器> run clear @s [物品 [数量]]。数量必须先写出物品；上限是 2147483647。

秒表（stopwatch）

原版秒表保存在世界数据里，/reload 不会清空，重复 create 会失败；需要保证只创建一次时用计分标志（见完整示例 tour_entities）。stopwatch.query秒表.查询 的缩放是可选数字，省略时为 1。

给予物品（give）

第一条把物品定义交给查询里的玩家；origin投掷者（中文 origin投掷者）投向当前实体的来源实体，要求实体上下文。数量必须在 1 到 max_stack_size × 100 之间。

self.item自身.物品 是把当前实体的物品原样交给玩家：要求实体上下文且不能指定数量，生成物会额外写出 data/<命名空间>/slot_source/__mcl/empty_slot.json，命令把实体槽 0（掉落物的物品）复制到目标玩家背包的第一个空槽，复制成功才清空源槽；目标背包满了就不动源实体。

世界与方块

世界命令的参数也由编译器检查：坐标范围、方块资源位置、方块属性字符、枚举值、时间单位与数值范围都在编译期验证。位置统一写成 pos(<x>, <y>, <z>)坐标(<x>, <y>, <z>)（中文 pos(...)坐标(...)）：分量可以是整数绝对坐标、~[±偏移] 相对坐标或 ^[±偏移] 局部坐标；^ 三个分量必须同时使用，不能与另外两种混用。绝对坐标的水平范围是 -30000000 到 29999999，垂直范围是 -2032 到 2031。

方块写成 block_state("<命名空间:方块>") { <属性> = "<值>"; }方块状态("<命名空间:方块>") { <属性> = "<值>"; }（中文 block_state(...)方块状态(...)），属性块可省略；属性名只能是小写字母、数字与下划线，属性值只能是小写字母、数字与 _ . + -。block_state("#标签")方块状态("#标签") 是方块谓词，只能用在 fill填充 的替换过滤器与 clone复制 的 filtered过滤 选项里，也不能带属性。

常见问题

为什么 return返回 不能写在 if如果 里？

Minecraft 的 return返回 只结束当前 .mcfunction。Mclang 的 if如果、while当、each遍历 等结构会展开成辅助函数，块里的 return返回 只会结束辅助函数，与作者预期不符。需要条件返回值时，先给局部变量赋值，在函数最外层末尾统一 return返回。

为什么带参数的函数不能直接 schedule调度 或被原版 /function 调用？

参数保存在函数私有的固定计分项里，调用方负责写值。schedule调度 发生在未来的游戏刻，原版 /function 也不会绑定参数，所以两者都只能看到上次留下的值。需要延时触发的参数化逻辑，请包一层无参数函数，由它写参数后调用真正的函数。

/reload 会重置计分变量、存储和秒表吗？

不会。计分板、storage存储 与秒表都属于世界存档数据。__mcl/load 只创建缺失的 objective、给缺失的计分变量补初始值、把 item_list物品列表 存储补成空列表；已有值保持原样。需要每次加载都重置的状态请显式赋值。

为什么声明名只能用 ASCII？

数据包最终落在文件系统上，函数名与文件名一一对应。编译器把声明名限制为小写 ASCII 字母、数字与下划线且不超过 32 字节；函数名与命名空间还会拒绝 Windows 保留设备名（CON、NUL、COM1 等），资源路径的每个文件名段同样受限，保证产物在常见平台上都能落地。中文关键词不改变这一点：标识符保持 ASCII，关键词可以随便写。

while当 会一直循环到什么时候？

while当 的循环体和条件互相调用，每轮消耗命令链预算。请在循环体里修改条件涉及的计分变量；如果条件永远成立，最终会撞上 Minecraft 的命令链长度限制。

两种关键词写法的产物真的一样吗？

是的。构建脚本会把文档里的每个完整示例翻译成英文与中文两版，分别用编译器构建，并逐文件比较字节；以 --self-test 运行时，仓库 examples/ 下的全部示例也会做同样的往返验证。任何翻译或实现偏差都会让构建失败。
