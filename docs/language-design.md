# Mclang 语言设计方向

## 产品目标

Mclang 源码应表达 Minecraft 行为，而不是要求作者先会写 mcfunction 再把命令塞进字符串。编译器负责实体选择器、`execute` 上下文、NBT 路径、文本组件 JSON、计分板 ABI、函数标签和目标版本目录等实现细节。

判断一个功能是否进入语言标准层的准则是：作者能否用有名称、有结构、可补全且可静态检查的语法描述意图。只能原样复制字符串的功能不算完成。

## 当前标准层

0.5 版继续建立第一批 Minecraft 类型：

- `query`：声明可复用的实体查询，并结构化描述类型、标签、距离、排序、数量和物品组件条件。
- `storage ... = items(...)`：声明保存完整物品堆和槽位的容器存储；编译器负责首次初始化。
- `item ... = item_stack(...)`：声明可复用的物品值，包括数量、名称、Lore、附魔、损伤、最大损伤、最大堆叠、稀有度、物品模型、染色、附魔光效覆盖和无法破坏。
- `give(目标查询, 物品, 数量)`：对应原版 `give <目标> <物品> [<数量>]`，目标必须是玩家查询，数量按 `GiveCommand` 的 `最大堆叠数 × 100` 规则检查；`self.give_item` 是当前玩家上下文的简写。
- `each`：逐个进入查询结果的实体及位置上下文。
- `spawn`：生成实体并在新实体上下文中执行初始化代码。
- `in_dimension`：切换维度执行上下文。
- `self.*`：修改当前实体标签和无敌状态，保存、恢复或清空容器，消费或移除实体；`remove_preserving_items` 封装安全收起容器的不变量，`return_to_owner` 把掉落物原样交还投掷者。
- `message.*`：用普通文本和颜色生成合法文本组件，不要求作者手写 JSON 或玩家选择器。
- `sound.self`：用经过检查的声音资源位置和分类播放声音。
- `predicate(...)`：把声明的数据包 predicate 作为普通布尔条件组合。
- `@entity`：标记要求实体执行上下文的函数；调用位置和调度限制由编译器检查。
- `@player`：标记要求玩家执行上下文的函数；玩家专用操作不会误用于普通实体。

这些结构在 AST 中都有独立节点。后端才把它们转换为 26.3-rc-2 命令，因此以后目标版本改变时可以替换后端映射，而不要求项目源码到处修改字符串。

0.5 版为所有语言结构提供中英文双关键词。别名只存在于词法和解析边界，进入 AST 前统一成规范形式，所以双语不会复制类型检查规则或代码生成器，也可以在同一项目中自由混用。

## 底层兼容边界

旧的 `run` 和字符串形式 `execute` 暂时保留，定位等同于其他语言的外部函数接口或内联汇编。它们不属于常规应用代码，编译器也无法验证字符串中的 Minecraft 语义。标准库尚未覆盖的能力应先记录缺口，再加入类型化语法；实际项目只有在目标版本确实存在未建模能力时才使用底层接口。

`check` 和 `build` 的 `--deny-raw` 选项把这条边界变为可执行策略。启用后，任意深度代码块中的 `run` 或字符串 `execute` 都会导致项目失败。

## 后续扩展顺序

1. 为方块、坐标、玩家、物品堆、效果、声音、粒子和战利品建立类型化值与操作。
2. 将查询条件扩展为组合谓词，并从 26.3 命令树和注册表生成资源位置、槽位及枚举校验数据。
3. 增加实体引用和类型化函数参数，减少对隐式 `self` 上下文的依赖。
4. 增加结构化 NBT 数据类型和数据包资源 schema，使字段错误在编译期出现。
5. 建立中间表示和版本后端，让同一份高层源码可以明确选择兼容的 Minecraft 目标。
6. 为编辑器提供格式化、补全、跳转、悬停类型和即时诊断。

每一阶段都用无底层命令字符串的实际项目验收；生成的 mcfunction 只作为编译产物检查，不作为作者接口。
