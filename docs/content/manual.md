## 认识 Mclang {#intro}

手写 `.mcfunction` 时，一个“每五秒给所有玩家发一次奖励”就需要同时处理计分板假玩家、`execute as`/`at` 上下文、函数标签、`tellraw` 的 JSON 和 `give` 的物品组件语法。Mclang 把源码分成了明确的层：

- **声明层**：`namespace`、`score`、`query`、`item`、`storage`、`resource`、`fn_tag`、`fn`，编译器检查重名、类型与资源位置。
- **语句层**：`each`、`spawn`、`give`、`self.*`、`message.*`、`effect.*`、`xp.*`、`schedule`、`if`/`while` 以及 `set_block`、`fill`、`clone` 等世界命令，每条都是独立 AST 节点。
- **表达式层**：整数、计分值、带返回值的函数调用与 `xp.query`、`stopwatch.query`、`time.query`、`gamerule.query`、`worldborder.get` 等查询表达式。
- **逃生口**：`run` 与 `execute` 接受原生命令字符串，`--deny-raw` 可以强制项目完全停留在标准层。

:::tip 中英关键词完全等价
每个关键词、函数属性、方法和枚举值都有英文与中文写法，两种写法可以在同一个文件、同一条语句里混用。编译器保证两种写法生成**逐字节相同**的数据包；本手册的构建脚本会在每次生成时重新验证这一点。
:::

```mcl title="一个最小的完整程序" verify id=hello
namespace hello;

score ticks = 0;
query all_players = entity("minecraft:player") {}

@load
fn load() {
    message.all("Hello from Mclang", green);
}

@tick
fn tick() {
    ticks += 1;
    if ticks >= 100 {
        each(all_players) {
            message.self("Five seconds passed.", gold);
            sound.self("minecraft:block.note_block.pling", master);
        }
        ticks = 0;
    }
}
```

## 安装与第一个数据包 {#quickstart}

### 构建编译器

需要 Rust 工具链（edition 2024，依赖只有 `serde_json`）：

```powershell title="构建"
cargo build --release
```

可执行文件是 `target/release/mclang.exe`；开发时也可以直接用 `cargo run -- <参数>`。

### 命令行

```text title="用法"
mclang build <源文件.mcl|项目目录> [-o <输出目录>] [--description <文本>] [--deny-raw]
mclang check <源文件.mcl|项目目录> [--deny-raw]
mclang lsp
mclang help | version
```

| 命令 | 作用 |
| --- | --- |
| `mclang check <输入>` | 只做检查、不写文件，全部诊断一次返回，通过后打印资源统计 |
| `mclang build <输入> [-o 目录]` | 通过全部检查后写出数据包，默认输出到 `build/<名字>` |
| `--deny-raw` | 严格模式：项目里出现任何 `run`、字符串 `execute` 或 `return run` 就拒绝构建 |
| `--description <文本>` | 写入 `pack.mcmeta` 的描述，默认 `Generated by mclang` |
| `mclang lsp` | 在标准输入输出上启动语言服务器，供编辑器插件使用 |

输入可以是单个 `.mcl` 文件，也可以是递归包含 `.mcl` 的目录；同一个项目里的所有文件必须声明相同命名空间，声明与引用在整个项目内可见。

```powershell title="检查并构建示例"
cargo run -- check examples/portable_chest --deny-raw
cargo run -- build examples/portable_chest --deny-raw
```

把输出目录复制到世界的 `datapacks/` 下，执行 `/reload` 即可。数据包格式固定为 `121.0`。

## 语言基础 {#basics}

### 注释、字符串与数字

- 注释：`// 到行尾`，没有块注释。
- 字符串：双引号，支持转义 `\"`、`\\`、`\n`、`\r`、`\t`，不能跨行。
- 原始字符串：`"""` 到下一个 `"""`，可以跨行，内容不做转义——适合内嵌 JSON。
- 数字：十进制整数（32 位范围内）与小数（`1.5`、`0.25`）。
- 标识符：字母、数字与下划线，不能以数字开头。声明名（函数、计分变量、查询、物品、存储、函数标签、参数与局部变量）必须是小写 ASCII 字母、数字与下划线，不超过 32 字节，且不能是保留字。

### 程序结构与命名空间

每个文件都以 `namespace <名称>;` 开头。项目里所有文件必须声明同一个命名空间；命名空间只能包含小写 ASCII 字母、数字与下划线，不能以数字开头，也不能是 Windows 保留设备名。声明顺序不影响引用。

### 中英关键词

下表只是示例，完整对照见[附录 A](#appendix-keywords)：

| English | 中文 | English | 中文 |
| --- | --- | --- | --- |
| `namespace` | `命名空间` | `fn` | `函数` |
| `score` | `计分` | `query` | `查询` |
| `item_stack` | `物品堆` | `each` | `遍历` |
| `if` | `如果` | `else` | `否则` |
| `give` | `给予` | `schedule` | `调度` |
| `message` | `消息` | `self` | `自身` |
| `@load` | `@加载` | `@tick` | `@每刻` |

### 执行上下文 {#basics-context}

Mclang 用四种上下文描述“这段代码在谁身上执行”，编译器据此拒绝错误的实体操作：

| 上下文 | 来源 | 含义 |
| --- | --- | --- |
| 无 | `@load`、`@tick` 入口函数 | 没有执行实体，`@s` 不可用 |
| 任意实体 | `@entity` 函数 | 有实体，但可能是玩家 |
| 非玩家实体 | 非玩家查询的 `each`、`spawn` 块、`@non_player` 函数 | 确定不是玩家 |
| 玩家 | 玩家查询的 `each`、`@player` 函数 | 确定是玩家 |

非玩家实体与玩家都是“任意实体”的特例，但互不包含：Minecraft 拒绝 `data ... entity` 修改玩家数据，所以 `self.save_items` 这类 NBT 操作只允许非玩家实体上下文；玩家专用操作（`message.self`、`self.give_item`、`xp.*`）反过来只允许玩家上下文。

## 顶层声明 {#declarations}

### 计分变量（score）

```mcl title="语法" fragment
score <name> = <整数>;
```

声明一个全局计分变量并给出初始值（32 位有符号整数，可带负号）。变量保存在计分板假玩家 `#v_<name>` 上，随世界存档持久化；`/reload` 只会在缺少时补写初始值，不会把已有值重置。

```mcl title="示例" fragment
score ticks = 0;
score penalty = -5;
```

### 实体查询（query）

```mcl title="语法" fragment
query <name> = entity("<实体类型>") {
    tag("<实体标签>");
    without_tag("<实体标签>");
    limit(<数量>);
    within(<距离>);
    sort(nearest | furthest | random | arbitrary);
    item(contents) {
        id = "<物品类型>";
        count = <数量>;
        custom_name = "<文本>";
    }
}
```

查询是一段可复用的选择器。`limit`、`within`、`sort`、`item` 各只能出现一次；`item` 过滤器里的 `id` 必填，槽位目前只支持 `contents`。查询不产生命令，只在 `each`、`give`、`effect`、`xp`、`clear` 里被引用。

| 属性 | 生成的参数 | 中文写法 |
| --- | --- | --- |
| `tag("t")` | `!tag=t` | `标签("t")` |
| `without_tag("t")` | `!tag=!t` | `排除标签("t")` |
| `limit(3)` | `!limit=3` | `上限(3)` |
| `within(16)` | `distance=..16` | `范围(16)` |
| `sort(nearest)` | `!sort=nearest` | `排序(最近)` |
| `item(contents) { id = … }` | `if items entity @s contents …` | `物品(内容) { 类型 = …; }` |

`xp.query` 要求目标查询带 `limit(1)`，否则编译期报错。

```mcl title="示例" fragment
query nearby = entity("minecraft:player") { within(16); sort(nearest); }
query one = entity("minecraft:player") { limit(1); }
query gems = entity("minecraft:item") {
    without_tag("picked");
    item(contents) {
        id = "minecraft:emerald";
        count = 1;
        custom_name = "A";
    }
}
```

`each(q)` 对玩家查询生成 `execute as @e[type=minecraft:player,…] at @s …`，对非玩家查询则在选择器之后追加 `if items …` 谓词。

### 物品定义（item / item_stack）

```mcl title="语法" fragment
item <name> = item_stack("<物品类型>") {
    count = <数量>;
    custom_name = "<文本>";
    item_name = "<文本>";
    lore("<文本>");
    enchantment("<附魔>", <等级>);
    stored_enchantment("<附魔>", <等级>);
    damage = <整数>;
    max_damage = <整数>;
    max_stack_size = <整数>;
    rarity = common | uncommon | rare | epic;
    item_model = "<模型资源位置>";
    dyed_color = <RGB>;
    enchantment_glint_override = true | false;
    unbreakable = true | false;
}
```

物品定义是一段可复用的物品组件文本。`count` 默认 1；`lore`、`enchantment`、`stored_enchantment` 可以写多行；组件输出顺序固定，与声明顺序无关。`max_stack_size` 大于 1 时不能再声明 `max_damage`。`give` 的数量上限是 `max_stack_size × 100`（未声明最大堆叠数时按 1 计算，因此上限 100）。

```mcl title="示例" fragment
item reward = item_stack("minecraft:diamond_pickaxe") {
    count = 1;
    custom_name = "开拓者之镐";
    item_name = "钻石镐";
    lore("由 Mclang 生成");
    enchantment("minecraft:efficiency", 3);
    rarity = rare;
    unbreakable = true;
}
```

### 物品列表存储（storage）

```mcl title="语法" fragment
storage <name> = item_list("<存储资源位置>", "<NBT 路径>");
```

存储是 `self.save_items`/`self.restore_items` 使用的容器位置。`__mcl/load` 会在首次加载时把路径初始化为空列表，`/reload` 不会清空已有内容。

```mcl title="示例" fragment
storage saved_items = item_list("portable_chest:state", "saved_items");
```

### JSON 资源（resource）

```mcl title="语法" fragment
resource predicate <name> = """{ ... }""";
```

声明一份原样写出的 JSON 资源，编译后保存到 `data/<命名空间>/<类型>/<名称>.json`。可用的类型是 26.3 的资源目录名（见[附录 C](#appendix-registry)），其中 `predicate` 可以在条件里用 `if predicate(<name>)` 引用；其他类型写英文名称，带斜杠的类型要写成字符串名称（例如 `"worldgen/feature/example"`）。JSON 会在编译期解析，格式错误直接报告行列位置，输出时统一重排为两空格缩进。

```mcl title="示例" fragment
resource predicate coin_flip = """
{
  "condition": "minecraft:random_chance",
  "chance": 0.5
}
""";
```

### 函数标签（fn_tag）

```mcl title="语法" fragment
fn_tag <name> {
    value(<本命名空间函数>);
    value(#<本命名空间标签>);
    value("<外部函数资源位置>");
    value("#<外部标签资源位置>");
    replace = true | false;
}
```

函数标签输出到 `data/<命名空间>/tags/function/<名称>.json`，供 `call #标签()` 与 `schedule #标签() after …` 使用。`replace` 为真时写出 `"replace": true`，覆盖同名低优先级标签；默认是假，即与低优先级数据包合并。标签引用的本命名空间函数与标签必须存在，循环引用会被拒绝；字符串形式的外部引用只校验资源位置。调用标签时编译器会展开标签里的全部函数，检查它们的参数与上下文要求。

```mcl title="示例" fragment
fn_tag batch {
    value(prepare);
    value(#announcement);
}
```

### 函数与属性（fn）

```mcl title="语法" fragment
[@load | @tick | @entity | @player | @non_player]
fn <name>(<参数>...) [-> score] {
    ...
}
```

函数可以带任意多个参数，可以声明返回一个计分值（`-> score`）。返回值有两种形式：表达式（写进临时计分项后 `return run scoreboard players get …`）或 `return run "<命令>"`。带返回值的函数必须以 `return` 结束。

| 属性 | 含义 | 限制 |
| --- | --- | --- |
| `@load` | 服务器加载/`/reload` 时运行 | 不能带参数、不能返回值，不能与实体属性同用 |
| `@tick` | 每游戏刻运行 | 同上；`tick.json` 的顺序与源码一致 |
| `@entity` | 要求任意实体上下文 | 与 `@load`/`@tick` 互斥 |
| `@non_player` | 要求非玩家实体上下文 | 与另外两个实体属性互斥 |
| `@player` | 要求玩家上下文 | 与另外两个实体属性互斥 |

参数保存在函数私有的固定计分项 `#p_<哈希>` 里，调用方负责写值；**从 Minecraft 直接调用参数化函数不会重新绑定参数**，会沿用上次留下的值，所以参数化函数只应从 Mclang 调用。参数名不能与全局计分变量重名，函数内也不能重复声明。

## 语句参考 {#statements}

### 控制流（if / else / while）

```mcl title="语法" fragment
if <条件> {
    ...
} else {
    ...
}

while <条件> {
    ...
}
```

`if` 与 `while` 保持当前执行上下文，不引入新实体。编译时条件会求值为 0/1 的临时计分项：`if` 生成 `execute if score <flag> matches 1 run function <辅助函数>`，`else` 分支用 `matches 0`；条件里的 `&&`、`||`、`!`、比较与 `predicate(…)` 也都会下降成计分板操作。

**`return` 只能直接出现在函数最外层代码块**，不能放进 `if`、`while`、`each`、`spawn`、`in_dimension` 或 `execute` 块——这些结构会展开成辅助函数，块里的 `return` 只会结束辅助函数。需要条件结果时先给局部变量赋值，在函数末尾统一 `return`。

```mcl title="示例" fragment
if ticks >= 100 {
    message.all("整点", gold);
} else {
    if ticks % 20 == 0 {
        message.all("滴答", gray);
    }
}
```

`while` 的循环体与条件互相调度，运行时上限由 Minecraft 的命令链长度决定；请确保每次迭代都会改变条件里的计分变量。

```mcl title="语法" fragment
let <name> = <表达式>;
<name> = <表达式>;
<name> += <表达式>;   // 还有 -=、*=、/=、%=
```

`let` 声明只在函数（块）内可见的局部变量，作用域不能遮蔽全局计分变量或参数。除零在编译期直接拒绝（右操作数是常量 0 时）。

### 遍历实体（each）

```mcl title="语法" fragment
each(<查询>) {
    ...
}
```

对查询结果逐个执行块内语句，并建立新的执行上下文：玩家查询进入玩家上下文，其他类型进入非玩家实体上下文。块会展开成辅助函数，生成 `execute <选择器> run function <命名空间>:__mcl/<函数>/<n>`。

```mcl title="示例" fragment
each(all_players) {
    self.give_item(reward);
    message.self("五秒到", gold);
}
```

### 生成实体（spawn）

```mcl title="语法" fragment
spawn("<实体类型>") {
    ...
}
```

在当前执行位置生成实体，块内的 `self` 指向新实体，总是进入非玩家实体上下文。`minecraft:player` 与 `minecraft:fishing_bobber` 在 26.3 中标记为不可召唤，编译器直接拒绝。生成 `execute summon <类型> run function <辅助函数>`。

```mcl title="示例" fragment
spawn("minecraft:chest_minecart") {
    self.add_tag("box");
    self.set_invulnerable(true);
}
```

### 维度上下文（in_dimension）

```mcl title="语法" fragment
in_dimension("<维度资源位置>") {
    ...
}
```

块内语句在指定维度执行，执行上下文保持不变。生成 `execute in <维度> run function <辅助函数>`。

### 原生执行子句（execute）

```mcl title="语法" fragment
execute "<子句>" {
    ...
}
```

块内语句在一个额外的原版 `execute` 上下文中运行，子句字符串只写参数部分，例如 `"as @a at @s"` 或 `"positioned ~ ~ ~ facing entity @s"`。字符串不能为空、不能跨行、不能以 `execute ` 或 `run ` 开头、也不能以 ` run` 结尾；`execute` 语句计入 `--deny-raw`。

```mcl title="示例" verify id=execute_demo raw
namespace execute_demo;

query all_players = entity("minecraft:player") {}

@load
```

### 函数调用（call）

```mcl title="语法" fragment
call <函数>(<实参>...);
call #<函数标签>();
<函数>(<实参>...);              // 省略 call 的等价写法
let <name> = <函数>(<实参>...);   // 返回 score 的函数可用于表达式
```

调用会先从左到右求值实参、写入被调用函数的参数计分项，再执行 `function <命名空间>:<函数>`。实参个数、执行上下文要求不符会编译报错；函数标签不能传参，标签里任何需要参数或上下文的函数都会让调用点报错。

```mcl title="示例" fragment
let half = divide(10, 4);
call announce();
call #batch();
```

### 调度（schedule）

```mcl title="语法" fragment
schedule <函数>() after <时间> [append | replace];
schedule #<函数标签>() after <时间> [append | replace];
schedule.clear(<函数>);
```

`after` 接受“数字 + 单位”：`t`（游戏刻）、`s`（秒）、`d`（天），可带小数，例如 `after 2.5 s`；换算按原版 `TimeArgument` 四舍五入。模式默认 `replace`，`append` 追加一次调度。被调度的函数与标签成员必须**无参数、无执行上下文要求**——调度发生在未来的游戏刻，不会保留实体或玩家。`schedule.clear` 取消尚未执行的同名调度，只接受函数、不接受标签。

```mcl title="示例" fragment
schedule heartbeat() after 20 t replace;
schedule #batch() after 1.5 s append;
schedule.clear(heartbeat);
```


```mcl title="示例" fragment

message.nearest(16, "你附近有动静", yellow);
```

### 给予物品（give）


### 世界与方块 {#statements-world}

世界命令的参数也由编译器检查：坐标范围、方块资源位置、方块属性字符、枚举值、时间单位与数值范围都在编译期验证。位置统一写成 `pos(<x>, <y>, <z>)`（中文 `坐标(...)`）：分量可以是整数绝对坐标、`~[±偏移]` 相对坐标或 `^[±偏移]` 局部坐标；`^` 三个分量必须同时使用，不能与另外两种混用。绝对坐标的水平范围是 -30000000 到 29999999，垂直范围是 -2032 到 2031。

方块写成 `block_state("<命名空间:方块>") { <属性> = "<值>"; }`（中文 `方块状态(...)`），属性块可省略；属性名只能是小写字母、数字与下划线，属性值只能是小写字母、数字与 `_ . + -`。`block_state("#标签")` 是方块谓词，只能用在 `fill` 的替换过滤器与 `clone` 的 `filtered` 选项里，也不能带属性。

```mcl title="语法" fragment
set_block(<位置>, <方块状态>[, destroy | keep | replace | strict]);
fill(<起点>, <终点>, <方块状态>[, replace | outline | hollow | destroy | strict | keep][, <替换过滤器>]);
fill_biome(<起点>, <终点>, "<生物群系>"[, replace, "<生物群系或标签>"]);
clone(<起点>, <终点>, <目标位置>[, <选项>...]);
place.feature("<地物>"[, <位置>]);
place.structure("<结构>"[, <位置>]);
place.jigsaw("<模板池>", "<拼图目标>", <最大深度>[, <位置>]);
place.template("<模板>", <位置>[, <旋转>[, <镜像>[, <完整度>[, <随机种子>[, strict]]]]]);
forceload.add(<列坐标>[, <列坐标>]);
forceload.remove(<列坐标>[, <列坐标>]);
forceload.remove_all();
```

| 语句 | 生成的命令 |
| --- | --- |
| `set_block(pos, block[, mode])` | `setblock <x y z> <block[属性]> [mode]` |
| `fill(from, to, block[, mode][, filter])` | `fill <x y z> <x y z> <block[属性]> [mode] [replace <过滤器>]` |
| `fill_biome(from, to, "biome"[, replace, "filter"])` | `fillbiome … [replace <过滤器>]` |
| `clone(...)` | `clone [from <维度>] <起点> <终点> <目标> [to <维度>] [filtered <谓词> 或 masked] [force 或 move] [strict]` |
| `place.feature/structure/jigsaw/template` | `place feature/structure/jigsaw/template …` |
| `forceload.add/remove/remove_all/query` | `forceload add/remove/remove all/query …` |

补充规则：

- `clone` 的选项可以任意顺序书写，但每类最多一次：过滤方式是 `replace`（默认）、`masked` 或 `filtered <方块谓词>`；复制模式是 `normal`（默认）、`force` 或 `move`；`strict` 是一个标志；跨维度写成 `from_dimension("<维度>")` 与 `to_dimension("<维度>")`（中文 `起始维度`/`目标维度`）。输出顺序固定为 `from`、坐标、`to`、过滤、模式、`strict`。
- `fill` 的替换过滤器只能与 `replace` 模式一起使用。
- `place.jigsaw` 的最大深度是 1 到 20；`place.template` 的完整度是 0.0 到 1.0，旋转是 `none`、`clockwise_90`、`180`、`counterclockwise_90`，镜像是 `none`、`left_right`、`front_back`；要写后面的可选参数必须按顺序补齐前面的。
- 时间参数是“数字 + 单位”，单位 `t`/`s`/`d`（刻/秒/天），括号里可写逗号：`time.set(6000, t)`、`worldborder.set(1000, 5 s)`、`after 1.5 s`。`time.set` 的最小值是 0，`time.add` 允许负数，`weather` 持续时间至少 1 刻。
- `forceload` 用列坐标 `column(<x>, <z>)`（中文 `列坐标(...)`），不支持 `^`；一次 `add`/`remove` 影响的范围最多 256 个区块。
- 范围检查：`forceload.add`/`remove` 的列坐标、`worldborder` 的数值都会在编译期检查（`worldborder.set` 是 1 到 59999968，`center` 绝对值不超过 29999984，伤害参数非负）。
- `locate` 只产生命令反馈，不返回值；`gamerule.query`、`time.query`、`time.query_gametime`、`worldborder.get` 是表达式，可以赋值给计分变量。

## 表达式与条件 {#expressions}

表达式出现在赋值右侧、条件比较两侧与函数实参里：

| 表达式 | 说明 |
| --- | --- |
| `<整数>` | 32 位整数常量，纯常量表达式在编译期折叠 |
| `<计分变量>` | 全局计分变量、函数参数或局部变量 |
| `<函数>(<实参>...)` | 返回 score 的函数调用，结果写入临时计分项 |
| `xp.query(<查询>, points 或 levels)` | 读取经验值，要求 `limit(1)` |
| `stopwatch.query("<id>"[, <缩放>])` | 读取秒表，失败时为 0 |
| `time.query(["<时钟>"])` | 世界时钟的总游戏刻 |
| `time.query_gametime()` | 世界的游戏时间 |
| `gamerule.query("<规则>")` | 规则当前值 |
| `worldborder.get()` | 世界边界边长 |

运算符：一元 `-`，二元 `+`、`-`、`*`、`/`、`%`，括号分组；优先级与常见语言一致（`* / %` 高于 `+ -`）。除以常量 0 在编译期拒绝。

条件是表达式之间的比较：`==`、`!=`、`<`、`<=`、`>`、`>=`，配合 `!`、`&&`、`||`、括号与谓词检查：

```mcl title="语法" fragment
if predicate(<本命名空间谓词>) && ticks % 20 == 0 {
    ...
}
if !(ticks < 100) || ready == 1 {
    ...
}
```

:::note 条件如何求值
条件最终变成一个 0/1 的标志计分项：比较生成 `execute if/unless score A <symbol> B run scoreboard players set <flag> … 1`，`&&` 用两条 `if score … matches 1` 串联，`||` 分别置 1，`!` 先置 1 再在内部为 1 时清零。编译器为条件分配临时计分项（`#t<序号>`），同一份源码的分配结果稳定可复现。
:::

## 编译产物与运行模型 {#artifacts}

### 生成的名字

| 名字 | 含义 |
| --- | --- |
| `mcl_<哈希>` | 每个命名空间唯一的计分板 objective，哈希由命名空间决定 |
| `#v_<name>` | 全局计分变量的假玩家 |
| `#p_<哈希>` | 函数参数的私有槽位 |
| `#l_<哈希>` | 局部变量的私有槽位 |
| `#t<序号>` | 表达式与条件的临时值 |
| `__mcl/<函数>/<序号>` | 结构块展开出的辅助函数 |
| `__mcl/load` | 编译器合成的初始化函数 |

`load.json` 只包含 `<命名空间>:__mcl/load`；`__mcl/load` 先创建 objective、补齐缺少的计分变量初始值、初始化存储，再按源码顺序调用全部 `@load` 函数。`tick.json` 只在存在 `@tick` 函数时生成。每个 `.mcfunction` 以 `# Generated by mclang.` 开头。

### 可复现

输出使用 `BTreeMap` 与稳定哈希，不引入随机顺序；同一份源码总是生成同样的文件与内容，两种关键词写法的产物逐字节一致。资源 JSON 由 `serde_json` 统一重排，`pack.mcmeta` 的描述来自 `--description`。

## 常见问题 {#faq}

:::details 为什么 `return` 不能写在 `if` 里？
Minecraft 的 `return` 只结束当前 `.mcfunction`。Mclang 的 `if`、`while`、`each` 等结构会展开成辅助函数，块里的 `return` 只会结束辅助函数，与作者预期不符。需要条件返回值时，先给局部变量赋值，在函数最外层末尾统一 `return`。
:::

:::details 为什么带参数的函数不能直接 `schedule` 或被原版 `/function` 调用？
参数保存在函数私有的固定计分项里，调用方负责写值。`schedule` 发生在未来的游戏刻，原版 `/function` 也不会绑定参数，所以两者都只能看到上次留下的值。需要延时触发的参数化逻辑，请包一层无参数函数，由它写参数后调用真正的函数。
:::

:::details `/reload` 会重置计分变量、存储和秒表吗？
不会。计分板、`storage` 与秒表都属于世界存档数据。`__mcl/load` 只创建缺失的 objective、给缺失的计分变量补初始值、把 `item_list` 存储补成空列表；已有值保持原样。需要每次加载都重置的状态请显式赋值。
:::

:::details 为什么声明名只能用 ASCII？
数据包最终落在文件系统上，函数名与文件名一一对应。编译器把声明名限制为小写 ASCII 字母、数字与下划线且不超过 32 字节；函数名与命名空间还会拒绝 Windows 保留设备名（`CON`、`NUL`、`COM1` 等），资源路径的每个文件名段同样受限，保证产物在常见平台上都能落地。中文关键词不改变这一点：标识符保持 ASCII，关键词可以随便写。
:::

:::details `while` 会一直循环到什么时候？
`while` 的循环体和条件互相调用，每轮消耗命令链预算。请在循环体里修改条件涉及的计分变量；如果条件永远成立，最终会撞上 Minecraft 的命令链长度限制。
:::

:::details 两种关键词写法的产物真的一样吗？
是的。构建脚本会把文档里的每个完整示例翻译成英文与中文两版，分别用编译器构建，并逐文件比较字节；以 `--self-test` 运行时，仓库 `examples/` 下的全部示例也会做同样的往返验证。任何翻译或实现偏差都会让构建失败。
:::

## 完整示例：核心语法 {#examples-core}

下面的程序把声明、物品与谓词资源、函数标签、表达式、全部赋值运算符、`while`、`predicate` 条件、标签调用与两种调度模式放在一起：

```mcl title="tour_core.mcl" verify id=tour_core
// 核心语法导览：声明、表达式、控制流、调用、谓词与调度。
namespace tour_core;

score ticks = 0;
score total = 0;
score pending = 3;
score ratio = 0;

query all_players = entity("minecraft:player") {}

item welcome = item_stack("minecraft:apple") {
    count = 2;
    custom_name = "欢迎苹果";
}

resource predicate lucky = """
{
  "condition": "minecraft:random_chance",
  "chance": 0.25
}
""";

fn_tag rounding {
    value(announce);
    value(compute);
}

@load
fn load() {
    message.all("tour_core 已加载", green);
    let half = divide(10, 4);
    if half > 2 {
        message.all("表达式与调用正常", aqua);
    }
}

fn divide(left, right) -> score {
    return left / right;
}

fn compute() -> score {
    let base = divide(100, 5);
    let remainder = 100 % 7;
    total = base + remainder;
    total -= 1;
    total *= 2;
    total /= 3;
    total %= 7;
    ratio = 0;
    if total > 0 {
        ratio = total;
    }
    return ratio;
}

fn announce() {
    pending += 1;
    return;
}

@tick
fn tick() {
    ticks += 1;
    if predicate(lucky) && ticks >= 20 {
        let step = difference(ticks, 20);
        total += step;
        ticks = 0;
        call #rounding();
        schedule heartbeat() after 5 s replace;
        schedule cleanup() after 1 s append;
    } else {
        if ticks >= 100 {
            while pending > 0 {
                pending -= 1;
            }
            message.nearest(32, "计数器继续运行", gray);
        }
    }
}

fn difference(left, right) -> score {
    return left - right;
}

fn heartbeat() {
    message.all("heartbeat", dark_aqua);
    schedule heartbeat() after 20 t replace;
}

fn cleanup() {
    schedule.clear(cleanup);
    message.all("cleanup", yellow);
    return fail;
}
```

## 完整示例：实体与玩家操作 {#examples-entities}

下面的程序把实体上下文、查询过滤器、`give`、`self`、消息、效果、经验、清空、秒表与调度放在一起，覆盖除世界命令外的大部分标准层语句：

```mcl title="tour_entities.mcl" verify id=tour_entities
// 实体与玩家操作：查询过滤器、give、self、消息、效果、经验、清空与秒表。
namespace tour_entities;

score active = 0;
score ready = 0;

query all_players = entity("minecraft:player") {}
query one_player = entity("minecraft:player") { limit(1); }
query nearby_players = entity("minecraft:player") { within(16); sort(nearest); }
query dropped_gems = entity("minecraft:item") {
    without_tag("picked");
    item(contents) {
        id = "minecraft:emerald";
        count = 1;
        custom_name = "A";
    }
}
query boxes = entity("minecraft:chest_minecart") { tag("tour_box"); }

item gift = item_stack("minecraft:diamond") {
    count = 1;
    custom_name = "礼物";
    lore("来自 tour_entities");
    enchantment("minecraft:unbreaking", 1);
    rarity = rare;
}

storage saved = item_list("tour_entities:state", "saved");

@load
fn load() {
    message.all("tour_entities 已加载", green);
    call ensure_watch();
}

fn ensure_watch() {
    if ready == 0 {
        ready = 1;
        stopwatch.create("tour_entities:timer");
    }
}

@player
fn reward_player() {
    give(all_players, gift);
    give(one_player, gift, 5);
    self.give_item(gift, 2);
    message.self("这是你的礼物", gold);
    sound.self("minecraft:entity.player.levelup", player);
}

@entity
fn mark_picked() {
    self.add_tag("picked");
}

fn buff() {
    effect.give(nearby_players, "minecraft:speed", 30, 1, true);
    effect.give_infinite(one_player, "minecraft:night_vision");
    effect.clear(nearby_players);
}

fn adjust_xp() {
    xp.add(one_player, points, 25);
    xp.set(one_player, levels, 5);
    xp.add(one_player, points, -10);
    let level = xp.query(one_player, levels);
    if level >= 5 {
        message.all("等级已达标", aqua);
    }
}

fn tidy() {
    clear(nearby_players, "minecraft:glass_bottle", 8);
    clear(all_players);
}

fn timing() {
    stopwatch.restart("tour_entities:timer");
    if stopwatch.query("tour_entities:timer", 1000) >= 10000 {
        message.all("超过十秒", gold);
    }
    stopwatch.remove("tour_entities:timer");
}

@non_player
fn prepare_box() {
    self.add_tag("tour_box");
    self.set_invulnerable(true);
    self.restore_items(saved);
}

fn destroy_box() {
    each(boxes) {
        self.remove_preserving_items(saved);
    }
}

fn store_box() {
    each(boxes) {
        self.save_items(saved);
        self.clear_items();
        self.remove_tag("tour_box");
        self.remove();
    }
}

@tick
fn tick() {
    each(all_players) {
        reward_player();
    }
    each(dropped_gems) {
        mark_picked();
        if active == 0 {
            spawn("minecraft:chest_minecart") {
                prepare_box();
            }
            active = 1;
            message.nearest(16, "便携箱子已放出", green);
            give(origin, self.item);
        } else {
            in_dimension("minecraft:overworld") {
                destroy_box();
            }
            active = 0;
            message.nearest(16, "便携箱子已收起", gold);
            give(origin, self.item);
        }
    }
}
```
