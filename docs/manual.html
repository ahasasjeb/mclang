Mclang：写给人类的 Minecraft 数据包语言

Mclang 是一门把 .mcl 源码编译成 Minecraft Java Edition 数据包的小语言。它让你用命名、类型和结构化语法描述实体查询、物品、消息、调度与控制流，把选择器、execute 上下文、NBT 路径和文本组件 JSON 交给编译器生成。

结构化的 Minecraft 类型

实体查询、物品堆、物品存储、维度、粒子以外的常用操作都有专门的语法节点，而不是命令字符串。

错误在编译期出现

未知变量、错误参数个数、数量越界、无效资源位置、执行上下文不匹配都会在写数据包之前报告，并带文件、行列与源码标记。

中英文关键词等价

每个语言结构都有中文写法，可以在同一文件内自由混用；两种写法生成逐字节相同的产物。

可复现的产物

输出顺序稳定、不依赖随机数；.mclang-manifest 记录上次生成的文件，重建只清理自己的旧产物。

它解决什么问题

手写 .mcfunction 时，一个很简单的“每五秒给所有玩家发一次奖励”就需要同时处理计分板假玩家、execute as/at 上下文、函数标签、tellraw 的 JSON、give 的物品组件语法和 pack.mcmeta 的版本号。Mclang 让源码只描述意图：

@tick
fn tick() {
    ticks += 1;
    if ticks >= 100 {
        调用 announce();
        ticks = 0;
    }
}

编译后展开为一条条合法的 .mcfunction 命令，例如上面的 if 会生成预计算比较结果、再用两条 execute if score ... matches 1 run function 分派分支的辅助函数。

编译流水线

.mcl 源文件→ 词法分析→ 递归下降解析→ 多文件合并→ 语义检查（一次报告全部诊断）→ 代码生成→ 数据包目录

目标与边界

  • 目标版本固定：Minecraft Java Edition 26.3-rc-2，数据包格式 121.0。资源位置、注册表目录与命令签名都以仓库内随附的客户端源码为准。
  • 编译器用 Rust 实现，运行时不需要 Java：编译一次，把生成的目录放进世界的 datapacks/ 即可。
  • 不支持热更新语言语义：目前是原型期语言，语法与内部 API 可以随版本调整，不保留兼容层。
  • 不是命令包装器：run 与字符串形式的 execute 只是底层逃生口（类似内联汇编），常规项目应使用结构化语法，并用 --deny-raw 强制这一点。

本手册约定

语法模板中的 <名称> 表示占位符；代码块右上角可以一键复制。所有示例的完整程序都经过仓库内编译器实际编译验证；标注“片段”的代码只用于说明语法形状，不能单独编译。

顶栏的 “中文关键词 / English keywords” 按钮会把页面上的 Mclang 代码块、侧边目录、章节标题和正文行内关键词一起在两种写法之间切换。切换只替换关键词、属性、方法和枚举值，注释与字符串原样保留；生成的 .mcfunction、命令行、目录树和附录的双语对照表不参与切换。

快速上手 #

1. 构建编译器

需要 Rust 工具链（edition 2024；项目只依赖 serde_json）。

cargo build --release

可执行文件位于 target/release/mclang.exe。开发时也可以直接用 cargo run -- <参数>。

2. 命令行

命令作用
mclang build <源文件.mcl|项目目录> [-o <输出目录>] [--description <文本>] [--deny-raw]编译并写入数据包目录；默认输出到 build/<源文件名或目录名>
mclang check <源文件.mcl|项目目录> [--deny-raw]只做静态检查，不写任何文件；通过后打印资源统计
mclang help打印用法；-h、--help 等价
mclang version打印版本号；-V、--version 等价

-o 与 --output 等价。--deny-raw 会递归统计项目里的 run 和字符串 execute 语句，只要多于零条就让命令失败，适合要求全部使用标准层的新项目。

3. 第一个数据包

把下面这个文件保存为 counter.mcl（它也是仓库 examples/counter.mcl 的内容）：

namespace counter;

// score 是跨函数共享的 32 位整数。重新加载数据包不会重置已有值。
score ticks = 0;
score announcements = 0;

query all_players = entity("minecraft:player") { }

@load
fn load() {
    message.all("Counter data pack loaded", green);
}

@tick
fn tick() {
    ticks += 1;
    if ticks >= 100 {
        announce();
        ticks = 0;
    }
}

fn announce() {
    announcements += 1;
    each(all_players) {
        sound.self("minecraft:block.note_block.pling", master);
        message.self("Five seconds passed.", gold);
    }
}

fn announce_later() {
    schedule announce() after 5 s replace;
}

先做静态检查：

cargo run -- check examples/counter.mcl

输出：

检查通过：4 个函数，2 个计分变量，1 个实体查询，0 个物品定义，0 个物品存储，0 个 JSON 资源，0 条底层语句

再构建数据包：

cargo run -- build examples/counter.mcl
已生成 10 个文件：build\counter

其中 tick.mcfunction 的内容是：

# Generated by mclang.
scoreboard players add #v_ticks mcl_6c7416517c63 1
scoreboard players set #t0 mcl_6c7416517c63 100
scoreboard players set #t1 mcl_6c7416517c63 0
execute if score #v_ticks mcl_6c7416517c63 >= #t0 mcl_6c7416517c63 run scoreboard players set #t1 mcl_6c7416517c63 1

提示 生成的命令不必逐行读懂，但知道“用户变量是 #v_<名字>、每个命名空间只有一个 objective、条件先算成 0/1 标志再分派”后，排查问题会容易很多。细节见 编译产物与 ABI。

5. 放进世界并运行

  1. 把 build/counter 整个目录复制到存档的 <世界目录>/datapacks/counter。也可以直接构建到目标位置： 
    cargo run -- build examples/counter.mcl -o "C:/path/to/world/datapacks/counter" --description "My counter pack"
  2. 进入世界后执行 /reload。Minecraft 会读取 load 标签，调用 counter:__mcl/load：创建 objective、只在计分项不存在时写入初始值，然后依次调用所有 @load 函数。
  3. tick 标签每个游戏刻调用一次 counter:tick，五秒后消息和声音就会出现在所有玩家处。

再次执行 /reload 不会重置 ticks 的值：初始化语句是“若该计分项还不存在才写入”，这是有意的设计——数据包重载不应清空玩家的运行状态。

6. 项目目录与严格模式

把多个 .mcl 文件放在同一目录（可嵌套子目录），编译器会递归读取，跳过隐藏目录、target 和 build。目录里每个文件必须声明相同的命名空间，声明和引用在整个项目内可见：

cargo run -- check examples/multi_counter
cargo run -- build examples/multi_counter
cargo run -- check examples/portable_chest --deny-raw
cargo run -- build examples/portable_chest --deny-raw

portable_chest 是一个完全不含底层命令字符串的实际项目，展示类型化实体查询、物品组件匹配、跨维度执行和容器持久化。

7. 重建与清理规则

每次构建都会在输出目录写一个 .mclang-manifest，内容是本次生成的全部相对路径。下次构建先用它删除上一次的产物，再写新文件：

  • 只删除清单里列出的普通相对路径，清单损坏、包含绝对路径或 .. 时构建直接失败，避免越界删除。
  • 目录中的其他文件（比如你自己放的资源或文档）保持原样。
  • 输出顺序由 BTreeMap 保证稳定，同样的源码总是生成同样的文件集合。

语言基础 #

源文件与项目

  • 输入可以是单个 .mcl 文件，也可以是一个目录。目录会递归读取所有 .mcl 文件，跳过名字以 . 开头的目录、target 和 build，并按路径排序后合并。
  • 每个源文件的第一条声明必须是命名空间；同一项目内所有文件的命名空间必须一致，否则报告错误并指出冲突文件的位置。
  • 声明顺序不影响引用：函数、计分变量、查询、物品定义、存储和资源在整个项目中可见，跨文件互相引用没有问题。
  • 源文件按 UTF-8 读取。中文既可以出现在关键词、字符串和注释里，也可以出现在资源路径之外的所有文本位置。

注释

// 开始单行注释，直到行尾。注释不参与编译，也不影响产物。

// 整行注释
score ticks = 0; // 行尾注释

标识符与保留字

函数名、计分变量名、查询名、物品定义名、存储名和参数名共用一套命名规则：

规则说明
字符集只能包含小写 ASCII 字母 a-z、数字 0-9 和下划线 _
首字符必须是字母或下划线，不能是数字
长度不超过 32 个字节
大小写区分大小写；大写字母不合法，标识符必须是纯小写
保留字不能与语言关键词重名，见下表
额外限制函数名和命名空间不能使用 Windows 保留设备名（con、prn、aux、nul、com1–com9、lpt1–lpt9，不区分大小写），避免生成无法在 Windows 上创建的文件

不能用作标识符的保留字：namespace、score、query、entity、items、item、item_stack、storage、resource、fn、let、run、call、schedule、after、append、replace、if、else、while、execute、each、in_dimension、spawn、self、message、sound、predicate、player、return、true、false。

注意 资源位置（比如 minecraft:emerald、demo:state）遵循 Minecraft 自己的规则，可以使用命名空间前缀和路径段，不受上面的标识符规则限制。命名空间前缀和路径段的合法字符见静态检查。

字符串

普通字符串用双引号，支持五种转义：\"、\\、\n、\r、\t。其他转义会报错；字符串内不允许出现实际换行（需要多行文本时使用原始字符串）。

跨行原始字符串以三个双引号开始和结束，内容不处理任何转义，原样保留。它主要用来在源码里嵌入可读的 JSON：

namespace demo;

resource predicate coin_flip = """
{
  "condition": "minecraft:random_chance",
  "chance": 0.5
}
""";

命令字符串里如果需要引号，使用 \" 转义；run 与 execute 的字符串都只允许一行，具体限制见底层接口。

中英文双关键词

所有语言结构、属性、方法和枚举值都提供中文写法，解析器在构造 AST 时把它们规范化为同一内部表示，因此：

  • 两种写法可以在同一项目、同一文件、同一条语句里混用；
  • 两种写法生成逐字节相同的产物；
  • 函数名、变量名、查询名、存储名、命名空间和 Minecraft 资源位置始终是稳定的 ASCII/Minecraft 标识符，不会被翻译。

同一个 @tick 函数的两种写法：

@tick
fn tick() {
    ticks += 1;
    if ticks >= 100 {
        call announce();
        ticks = 0;
    }
}
@每刻
函数 tick() {
    ticks += 1;
    如果 ticks >= 100 {
        调用 announce();
        ticks = 0;
    }
}

上例中的 ticks、announce 是用户标识符，两种写法保持原样；只有关键词被替换。完整的中英文关键词对照表见附录。

运算符一览

类别记号说明
赋值= += -= *= /= %=写入计分值；复合赋值带算术运算
比较== != < <= > >=只能出现在条件里，两侧都是算术表达式
布尔! && ||组合条件与 predicate；优先级 ! > && > ||
算术+ - * / %乘除模优先于加减；一元负号优先级最高
标点@ ( ) { } ; , . ->属性前缀、分组、块、语句结束、参数分隔、成员访问、返回类型箭头

语句以分号结束；代码块用花括号；函数返回类型写作 -> score（中文 -> 计分）。

顶层声明 #

一个源文件由“命名空间 + 任意数量的顶层声明”组成。声明之间没有顺序要求，可以交错出现；只有命名空间必须写在最前面。

声明语法形状作用
命名空间namespace demo;包名；决定函数路径、objective 与资源输出位置
计分变量score ticks = 0;跨函数共享的 32 位整数
实体查询query q = entity("minecraft:item") { ... }可复用的实体集合与物品条件
物品定义item gift = item_stack("minecraft:emerald") { ... }可复用的物品堆与组件
物品存储storage s = items("demo:state", "saved_items");持久保存完整槽位列表的容器
JSON 资源resource predicate p = """{...}""";带校验的 JSON 数据包资源
函数@tick fn tick() { ... }可调用、可返回 score 的代码块

命名空间 #

namespace <名称>;      // 中文：命名空间 <名称>;

命名空间必须出现在文件最前面，并且只能由小写 ASCII 字母、数字和下划线组成、不能以数字开头、不能超过 32 字节、不能是 Windows 保留设备名。它同时决定：

  • 函数在数据包中的路径：data/<命名空间>/function/*.mcfunction；
  • objective 名：mcl_ 加上命名空间的稳定 FNV-1a 哈希（12 位十六进制），避免不同数据包互相覆盖计分板；
  • JSON 资源的输出位置：data/<命名空间>/<资源类型>/<资源名>.json。

为什么是哈希 两个不同名字空间在 Minecraft 里可能对应同样的合法 objective 名。用稳定哈希可以让名字空间保持人类可读，同时保证 objective 名不会冲突、生成结果可复现。

计分变量 score #

score <名称> = <整数>;   // 中文：计分 <名称> = <整数>;
  • 类型是有符号 32 位整数（−2147483648 到 2147483647）。初始值前的负号计入数值，超出范围会在解析时报错。
  • 计分变量是跨函数、跨刻共享的全局状态，可以出现在任何表达式和赋值左侧。
  • 初始值只在“该计分项尚不存在”时写入，因此 /reload 不会清空运行状态；想让 /reload 重置状态需要显式赋值。
  • 生成时每个全局变量对应一个 #v_<名字> 假玩家，运行在同一个 objective 下。
namespace demo;

score counter = 0;
score offset = -10;

fn reset() {
    counter = 0;
    offset = -10;
}

实体查询 query #

query <名称> = entity("<实体类型>") {
    tag("<标签>");            // 中文：标签("...")
    without_tag("<标签>");    // 中文：排除标签("...")
    limit(<数量>);            // 中文：上限(1)
    within(<距离>);           // 中文：范围(16)
    sort(nearest);             // 中文：排序(最近)
    item(contents) {           // 中文：物品(内容)
        id = "minecraft:emerald";
        count = 1;
        custom_name = "A";
    }
}
属性中文参数可重复约束
tag("x")标签实体标签可以，多个非空、不超过 1024 字节，只含 ASCII 字母数字与 _ - .
without_tag("x")排除标签实体标签可以，多个同上；与 tag 合并去重
limit(n)上限正整数只能一次1 到 2147483647
within(n)范围正整数只能一次1 到 30000000（生成 distance=..n）
sort(v)排序nearest / furthest / random / arbitrary只能一次中文：最近 / 最远 / 随机 / 任意
item(槽)物品槽位名只能一次26.3 首版只支持 contents / 内容 槽

item 子块描述一个物品组件条件，必须声明 id：

属性中文约束
id = "..."类型必填；合法的物品资源位置
count = n数量可选；1 到 99
custom_name = "..."自定义名称可选；要求物品的自定义名称组件值精确匹配给定文本；不能包含控制字符

查询本身不产生命令，只在 each、give 中展开为选择器。例如：

namespace demo;

query emerald_drops = entity("minecraft:item") {
    without_tag("handled");
    limit(1);
    within(16);
    sort(nearest);
    item(contents) {
        id = "minecraft:emerald";
        count = 1;
        custom_name = "A";
    }
}

@tick
fn tick() {
    each(emerald_drops) {
        run "say found the named emerald";
    }
}

上面的查询会生成选择器 @e[type=minecraft:item,tag=!handled,sort=nearest,limit=1,distance=..16]，并追加物品组件检查：

execute as @e[type=minecraft:item,tag=!handled,sort=nearest,limit=1,distance=..16] at @s if items entity @s contents minecraft:emerald[minecraft:custom_name={text:"A"},minecraft:count=1] run function demo:__mcl/tick/0

注意 实体类型为 minecraft:player 的查询在 each 和 give 中会建立玩家上下文；其他类型只建立普通实体上下文。这是后面所有 self.* 限制的来源，详见执行上下文。

物品定义 item #

item <名称> = item_stack("<物品资源位置>") {   // 中文：物品 <名称> = 物品堆("...")
    count = 1;                    // 数量
    custom_name = "显示名称";      // 自定义名称
    item_name = "基础名称";        // 物品名称
    lore("第一行");                // 描述，可重复，最多 256 行
    enchantment("minecraft:fortune", 2);        // 附魔，可重复
    stored_enchantment("minecraft:mending", 1); // 存储附魔，可重复
    damage = 4;                   // 损伤
    max_damage = 100;             // 最大损伤
    max_stack_size = 16;          // 最大堆叠
    rarity = rare;                // 稀有度
    item_model = "minecraft:leather_chestplate";// 物品模型
    dyed_color = 0xff0000;        // 染色；源码里十进制，0 到 16777215
    enchantment_glint_override = true;          // 附魔光效
    unbreakable = true;                         // 无法破坏
}

物品定义把可复用的物品堆（类型 + 组件）变成一个名字，供 give 和 self.give_item 引用。解析器把中英文属性规范化为同一字段，生成时再写成 26.3 的物品组件参数。

属性中文生成的组件约束
count = n数量（不生成组件）1 到 100（未声明 max_stack_size 时；声明后为 n × 100）；作为 give 省略数量时的默认值

物品存储 storage #

JSON 资源 resource #

resource <类型> <名称> = <JSON 字符串>;
// 中文：资源 <类型> <名称> = <JSON 字符串>;
  • 类型和名称都可以写成标识符或字符串。名称需要子目录时使用字符串，例如 resource advancement "story/custom" = """...""";。
  • 类型必须是 26.3 支持的资源目录，完整列表见附录；worldgen/* 一律使用字符串形式。
  • 解析器提供一个中文别名：资源 谓词 <名称> = ... 等价于 resource predicate ...；其他类型保持英文目录名。

函数与属性 #

@属性
fn <名称>(<参数列表>) -> score {   // -> score 可省略；中文 -> 计分
    ...
    return <表达式>;
}
属性中文含义
@load@加载数据包加载或 /reload 后调用。可以标记多个函数，按源码顺序调用
@tick@每刻每个游戏刻调用一次。可以标记多个函数
@entity@实体函数要求普通实体执行上下文，self.* 可以安全使用
@player@玩家函数要求玩家执行上下文，可以使用玩家专用操作

参数

  • 参数是函数私有的 32 位计分值，可以参与表达式和赋值。调用时实参从左到右求值，再复制到被调用函数的私有槽位。
  • 参数名不能与全局计分变量重名，函数内也不能重复声明同名参数。
  • 入口函数（@load/@tick）不能带参数；需要参数的函数不能直接 schedule，请调度一个无参数包装函数。
  • 参数化函数应由 Mclang 代码调用：直接从 Minecraft 执行它会沿用上次调用留下的参数值。

返回值

  • 函数默认没有返回值，用 return; 提前结束。追加 -> score 后，函数必须以 return <表达式>; 结束，调用可以出现在任意计分表达式中。
  • 返回 score 的函数里每个 return 都必须带表达式；无返回值函数只能用 return;。
  • return 只能直接位于函数最外层代码块，不能放进 if、while、each、spawn、in_dimension 或 execute 块：Minecraft 的 return 只会退出当前 .mcfunction，而这些块会生成辅助函数，放进去会改变控制流含义。需要条件结果时，先赋给局部变量，在函数末尾返回。
namespace early;

score total = 0;

fn clamp_low(value) -> score {
    let result = value;
    if result < 0 {
        result = 0;
    }
    return result;
}

fn main() {
    total = clamp_low(total - 5);
}
fn wrong(value) -> score {
    if value < 0 {
        return 0;   // 错误：return 不能放在 if 块里
    }
    return value;
}

fn also_wrong() {
    return 1;       // 错误：没有 -> score 的函数只能 return;
}

编译器会给出“return 只能直接出现在函数代码块中，不能放在 if、while、each、spawn、in_dimension 或 execute 块内”和“无返回值函数只能使用 return;”。

函数契约

  • 同一个函数上不能重复使用相同属性；@entity 与 @player 互斥；@entity/@player 不能与 @load/@tick 组合。
  • @load/@tick 不能声明参数，也不能返回值。
  • 需要执行上下文的函数、带参数的函数都不能被 schedule：原版调度不会保留执行实体，也不会携带参数。
  • 同步调用图里不允许任何直接或间接递归：递归会覆盖仍在使用的参数与表达式临时值。需要跨刻重复执行时用 schedule。

表达式与赋值 #

target = expr;   target += expr;   target -= expr;
target *= expr;  target /= expr;   target %= expr;

表达式由以下元素组成，优先级从低到高：

  1. +、-（左结合）
  2. *、/、%（左结合）
  3. 一元负号 -
  4. 整数常量、计分变量名、函数调用（返回 score）、括号分组

计分值全部是有符号 32 位整数，运算沿用 Minecraft 计分板的语义与溢出行为：

运算Minecraft 26.3 行为
/=Mth.floorDiv：向下取整（-7 / 2 得 -4）
%=Mth.positiveModulo：结果始终非负（-7 % 3 得 2）
除零 / 模零运行时整条命令失败。编译器只拒绝编译期能确定为 0 的除数，运行时出现的 0 仍然会失败
+= 等32 位有符号加法，溢出回绕

纯常量表达式会在编译期折叠（使用带检查的算术；折叠失败则不再当作常量）。含变量或调用的表达式生成计分板命令，临时结果存放在 #t<编号> 槽位里。

namespace arithmetic;

score counter = 0;
score scale = 3;

fn update() {
    counter = 10;
    counter += 1;
    counter -= 2;
    counter *= scale;
    counter /= 4;
    counter %= 20;
    counter = (counter + 3) * 2;
}

静态除零检查的两种形式：

counter /= 0;              // 错误：不能除以零
counter /= scale - scale;  // 错误：右侧常量折叠为 0

生成提示 counter += 1; 会生成更短的 scoreboard players add … 1；counter = 5; 直接生成 set；只有运行时的混合表达式才使用 scoreboard players operation。

局部变量 let #

let <名称> = <表达式>;   // 中文：令 <名称> = <表达式>;
  • 局部变量是函数私有的 32 位计分值，初始值可以引用全局变量、参数和此前声明的局部变量。
  • 采用词法块作用域：离开声明它的代码块后不可见，也不能在声明前使用。
  • 同一函数内不允许重名局部变量（即使位于不同分支），也不允许局部变量或参数与全局计分变量同名——这是为了让生成的私有槽位和诊断信息保持清晰。
  • 名称是解析时确定的：函数内有同名局部变量时，这个名字解析为局部变量；否则解析为参数或全局变量。
namespace scopes;

score total = 0;

fn update(amount) {
    let adjusted = amount * 2;
    total += adjusted;

    if adjusted > 10 {
        let excess = adjusted - 10;
        total += excess;
    }
}

条件分支 if #

if <条件> { ... } else { ... }
// 中文：如果 <条件> { ... } 否则 { ... }

条件由三种形式组合而成：

  • 比较：left == right、!=、<、<=、>、>=，两侧都是任意算术表达式（可以包含函数调用）。
  • predicate：predicate(名字)（中文 谓词(名字)），引用当前命名空间声明的 predicate 资源。
  • 组合：!、&&、|| 和括号，优先级 ! > && > ||。

条件在进入分支之前求值一次，结果冻结为 0/1 标志，再由两条 execute if score <标志> matches 1/0 分派 then / else 辅助函数。因此 then 分支修改参与比较的变量不会错误触发 else。组合条件按从左到右的确定顺序求值。

namespace branching;

score enabled = 1;
score ticks = 0;
score override = 0;

fn check() {
    if enabled == 1 && ticks < 100 || override == 1 {
        run "say active";
    } else {
        run "say waiting";
    }

    if enabled == 1 && !(ticks < 100 || override == 1) {
        run "say paused";
    }
}

没有 else if 语法：在 else 块里继续写 if 即可。条件表达式只读取计分值，没有副作用。

循环 while #

while <条件> { ... }   // 中文：当 <条件> { ... }
  • 每次迭代都重新计算条件，语法与 if 完全一致。
  • 循环由两个辅助函数实现：条件函数求值后调用循环体函数，循环体末尾再调用条件函数。运行时上限由世界的 maxCommandChainLength 决定，所以循环体必须推进退出条件。
  • 没有 break / continue；需要提前结束时改写条件或使用 if 包裹循环体。
  • 同步函数递归会被编译器拒绝，循环不受此限制（它不是递归，而是同一调用链中的重复调用）。
namespace looping;

score pending = 3;

fn drain() {
    while pending > 0 {
        pending -= 1;
        run "say processed one task";
    }
}

底层接口 run / execute #

Mclang 把未建模的能力留给两个逃生口，定位类似内联汇编。常规项目应优先使用结构化语法；--deny-raw 可以让项目强制拒绝它们。

run "<完整命令>";                    // 中文：原生命令 "<完整命令>";
execute "<execute 子句>" { ... }       // 中文：原生执行 "<子句>" { ... }

run

  • 字符串内容原样成为一行 .mcfunction 命令，不做实体、资源位置、NBT 或参数的静态检查。
  • 命令不要写开头的 /；不能为空、不能包含实际换行（\n 转义也会在生成的文件中变成换行，所以也只允许单行命令）。
  • 支持 \"、\\、\n、\r、\t 转义。

execute

  • 字符串只写 execute 和 run 之间的子句，例如 "as @a at @s"；不能为空、不能以 execute 开头、不能以 run 结尾。
  • 代码块编译为私有辅助函数并继承原版 execute 建立的执行者、位置、维度和朝向上下文；块内可以继续嵌套 if、execute 和其他语句（不能用 return）。
namespace rawdemo;

@load
fn load() {
    run "say hello from raw";
    execute "as @a at @s" {
        run "particle minecraft:happy_villager ~ ~1 ~ 0.2 0.2 0.2 0 3";
    }
}

生成的 load.mcfunction 与辅助函数：

# data/rawdemo/function/load.mcfunction
# Generated by mclang.
say hello from raw
execute as @a at @s run function rawdemo:__mcl/load/0

# data/rawdemo/function/__mcl/load/0.mcfunction
# Generated by mclang.
particle minecraft:happy_villager ~ ~1 ~ 0.2 0.2 0.2 0 3

--deny-raw 的计数规则 每条 run 计 1 条；每个字符串 execute 块本身计 1 条，再加上嵌套内容里的每一条。上面的例子共 3 条，所以严格模式会失败并提示“项目包含 3 条底层 run/execute 语句”。

check --deny-raw 的失败信息是“严格模式检查失败：…”；build --deny-raw 是“严格模式拒绝构建：…”。

执行上下文 #

Mclang 用三级上下文描述“这段代码在谁身上执行”：无上下文 < 实体 < 玩家。编译器在编译期跟踪当前上下文，拒绝把玩家专用操作用在普通实体上，也拒绝在无实体时使用 self。

无上下文
@load / @tick / 普通函数→ 实体上下文
each(非玩家查询) / spawn / @entity→ 玩家上下文
each(玩家查询) / @player

上下文如何建立与传递

位置块内上下文
@load / @tick / 未标注函数无上下文
@entity 函数实体
@player 函数玩家
each(玩家查询)玩家
each(其他查询)实体
spawn("...")实体（新生成的实体）
in_dimension("...")保持外层上下文
execute "..."保持外层上下文（原版 execute 可能改变执行者，但编译器以声明的上下文为准）

上下文要求

操作最低上下文
普通 self.*（标签、无敌、物品保存/恢复/清空、remove、consume）实体
self.give_item、message.self、sound.self玩家
give(...)、message.all、message.nearest、schedule、run无

函数调用同样检查：调用要求“当前上下文 ≥ 函数要求的上下文”。玩家上下文可以调用 @player 或 @entity 函数；普通实体上下文只能调用 @entity 函数。

常见错误与解决

错误信息包含原因解决
“self 方法需要实体执行上下文”在 @tick 等无上下文函数里直接用了 self放进 each/spawn 块，或给函数加 @entity
“self.give_item 需要玩家执行上下文”实体上下文或普通查询的 each 里给物品用玩家查询的 each，或加 @player，或改用 give(players, item)
“@player 函数 f 需要玩家执行上下文”从实体或无上下文处调用了 @player 函数外层先进入玩家查询的 each，或改用 @entity/普通函数
“不能调度需要执行上下文的函数”schedule 一个 @entity/@player 函数改为调度无上下文包装函数，让包装函数进入上下文
“@entity 和 @player 不能与 @load 或 @tick 用在同一个函数上”入口函数被同时标注上下文属性拆成两个函数

判断口诀 “谁身上执行”决定 self；“给谁”由查询决定。绝大多数上下文错误都能靠“把语句放进正确的 each 块”解决。

编译产物与 ABI #

这一节解释“编译后到底生成了什么”。理解这些约定能让你在读生成的 .mcfunction、排查与其它数据包的冲突时心里有数。

目录结构

<输出目录>/
├── pack.mcmeta                                   # min_format / max_format = [121, 0]
├── .mclang-manifest                              # 产物清单
└── data/
    ├── <命名空间>/
    │   ├── function/
    │   │   ├── <用户函数>.mcfunction
    │   │   └── __mcl/

计分板 ABI

每个命名空间只有一个 objective，名字是 mcl_ 加命名空间的稳定 FNV-1a 哈希（12 位十六进制）。所有数值都存放在它的假玩家槽位里：

槽位含义命名方式
#v_<名字>全局计分变量人类可读，直接使用变量名
#p_<12 位十六进制>函数参数函数名:参数名 的哈希
#l_<12 位十六进制>词法局部变量函数名:局部名 的哈希
#t<编号>表达式临时值按编译顺序递增

以 # 开头的名字在 Minecraft 里不会与真实玩家冲突。哈希保证“同样的函数名 + 参数名”跨平台、跨次编译得到同样的槽位。

初始化与入口标签

__mcl/load 的内容按固定顺序生成：

  1. scoreboard objectives add <objective> dummy
  2. 对每个 score 声明：execute unless score <槽> <objective> = <槽> <objective> run scoreboard players set <槽> <objective> <初始值>（只在计分项不存在时写初始值）
  3. 对每个 storage 声明：execute unless data storage <位置> <路径> run data modify storage <位置> <路径> set value []
  4. 按源码顺序调用所有 @load 函数

load.json 只包含 <命名空间>:__mcl/load；tick.json 包含全部 @tick 函数，顺序与源码一致。每个 .mcfunction 以 # Generated by mclang. 开头（空函数只有这一行）。

结构块如何展开

源码结构生成方式
if / while 条件求值到 0/1 标志槽位，再用 execute if score … matches 1 分派
if 的 then / else各一个辅助函数；else 为空时不生成

为什么禁止同步递归 表达式临时值 #t<编号> 是每个命名空间全局复用的。如果函数 A 在表达式求值途中同步调用回自己，外层尚未使用的临时值会被内层覆盖，结果不可预测。因此编译器拒绝同步调用图里的任何环；schedule 不算同步调用。while 循环不涉及重入，所以不受影响。

可复现性

  • 所有集合使用 BTreeMap 或稳定哈希，不引入随机顺序；同样的源码总是生成同样的文件与内容。
  • 函数、辅助函数、objective、参数与局部变量名都由输入唯一决定，跨平台一致。
  • pack.mcmeta 的描述来自 --description，默认 Generated by mclang。
  • 资源 JSON 通过 serde_json 重新格式化为两空格缩进，字段顺序保留源码中的顺序。

静态检查与诊断 #

编译分四个检查阶段，顺序是词法 → 语法 → 语义 → （通过后）代码生成。任何一步失败都不会写出数据包：

阶段检查内容报告方式
词法无法识别的字符、未闭合字符串、非法转义、整数过大一次报告该文件全部词法错误
语法缺失的 ;、{ }、( )、错误的语句形状每个文件报告第一个语法错误
语义命名、引用、范围、上下文、返回值、递归、JSON 等全部规则一次返回全部诊断，方便一次修完
严格模式--deny-raw 统计 run / 字符串 execute；build 在语义检查之前统计，check 在语义检查之后统计只要有零条以上底层语句就失败，绝不写出数据包

任何文件出现词法或语法错误时，语义阶段不会运行（因为无法构造完整的 AST）。项目内命名空间不一致也在合并阶段报告，并指向冲突文件。

诊断格式

每条诊断包含中文信息、文件路径、行列、源码行和标记范围。下面是真实输出：

错误：找不到计分变量 `missing`
 --> broken.mcl:7:16
  |
  7 |     counter += missing;
  |                ^^^^^^^

命令行里错误打印到标准错误，进程返回退出码 1；check 成功时打印资源统计，build 成功时打印生成的文件数量与输出目录。

检查清单

语义阶段覆盖的规则，按类别列出（括号内是典型错误信息）：

类别检查

常见问题 #

编译成功了，但进游戏后没有任何效果，从哪里查起？
  1. /datapack list 确认数据包已启用；如果显示为 disabled，用 /datapack enable 或检查输出目录是否在存档的 datapacks/ 下。
  2. 执行 /reload。如果 load 入口报错，游戏控制台会给出具体的函数名与命令。
  3. 确认 pack.mcmeta 的 min_format/max_format 是 [121, 0]，目标客户端是 26.3-rc-2。
  4. 检查 load.json / tick.json 里的函数引用是否与命名空间一致。
为什么 /reload 之后计分变量没有回到初始值？

这是有意设计：初始化命令是 execute unless score … run …，只在计分项不存在时写入，这样重载数据包不会清空运行状态。需要重置就显式赋值（例如在 @load 函数里写 ticks = 0;），但这同样会在每次重载时执行。

为什么带参数的函数被原版 /function 调用时，参数值是上一次的？

参数保存在函数私有的固定计分项里，调用方负责写值。从 Minecraft 直接调用一个参数化函数不会重新绑定参数，所以会沿用上次留下的值。正确做法是：只在 Mclang 代码里调用它，或为它写一个无参数包装函数供原版/调度使用。

为什么 schedule 提示“不能调度需要 N 个参数的函数”或“不能调度需要执行上下文的函数”？

原版 /schedule 在未来的游戏刻执行函数，不保留当前执行实体，也不携带参数。请调度一个无参数、不需要上下文的包装函数，把参数和上下文逻辑写在包装函数内部。详见调度。

while 循环会一直卡住吗？

不会无限执行，但会消耗命令链预算。循环由函数互相调用实现，运行时会受世界设置 maxCommandChainLength 限制；一旦达到上限，游戏会停止执行剩余命令并记录错误。请确保循环体推进退出条件，跨刻的重复执行用 schedule。

什么时候可以用 self？为什么总报“需要实体执行上下文”？

self 需要实体上下文，只有四种位置能提供：非玩家查询的 each 块、spawn 块、@entity 函数、@player 函数。玩家专用的 self.give_item、message.self、sound.self 还要求玩家上下文。把语句移进正确的块即可。

为什么 return 不能写在 if 里？

Minecraft 的 return 只退出当前 .mcfunction。Mclang 的 if、while、each 等结构会生成辅助函数，把 return 放进去只会结束辅助函数，含义与作者预期不符。需要条件结果时先给局部变量赋值，在函数最外层末尾 return。

可以用中文命名变量或函数吗？

不可以。标识符必须是纯小写 ASCII 字母、数字和下划线；中文只用于关键词、字符串、注释和资源路径之外的文本。查询名、物品名等同样遵循 ASCII 规则，因为生成的选择器与函数路径需要稳定。

中英文关键词可以混用吗？产物会不同吗？

可以任意混用，包括同一文件同一条语句。解析器立即把中文别名规范化为同一内部值，因此两种写法生成逐字节相同的产物；仓库测试里有一份 300 行的中英文对照程序断言 files 完全相等。

静态检查通过了，游戏加载却报资源 JSON 错误，为什么？

编译器只做三件事：确认类型受支持、路径合法、JSON 语法正确并按注册表目录写出。JSON 字段的 Minecraft codec 语义（必填字段、枚举值、类型）由游戏加载时验证。请对照目标版本的资源 schema 检查字段。

什么时候该用 run？

只在标准层确实没有覆盖目标能力时使用，并且把它当作“内联汇编”：字符串内容不受任何静态检查。建议先在新项目里打开 --deny-raw，遇到缺口时记录它，再考虑给语言加类型化语法。仓库现状：portable_chest 与所有单文件示例都通过了 --deny-raw。

objective 名可以自定义吗？

不可以。每个命名空间对应一个由稳定哈希生成的 mcl_<12 位十六进制> objective。这样做既避免不同数据包互相覆盖计分板，也保证生成结果可复现。如果两个数据包想共享状态，需要显式约定同一个命名空间之外的机制（例如命令存储或标签）。

为什么 give 的数量上限是 100 或 堆叠数 × 100？

这是 26.3 GiveCommand 自己的规则：MAX_ALLOWED_ITEMSTACKS = 100，数量不能超过物品最大堆叠数乘以 100。编译器在编译期借用同一规则，把错误提前暴露。未声明 max_stack_size 时物品原型的最小堆叠数是 1，所以保守上限是 100。

能不能一个项目里放多个命名空间？

不能。项目内所有 .mcl 文件必须声明相同的命名空间；不同数据包请分别构建到不同输出目录。合并时会检查一致性并指出冲突文件与位置。

如何升级到未来的 Minecraft 版本？

当前编译器把目标版本固定在 26.3-rc-2（数据包格式 121.0），没有版本选择参数。目标版本细节集中在代码生成与校验数据里，不散落在用户源码中。

设计理念 #

标准层准入准则

一个功能是否进入语言标准层，判断标准是：作者能否用有名称、有结构、可补全且可静态检查的语法描述意图。只能原样复制字符串的功能不算完成。

因此 Mclang 的源码表达 Minecraft 行为，而不是要求作者先会写 mcfunction 再把命令塞进字符串。编译器负责实体选择器、execute 上下文、NBT 路径、文本组件 JSON、计分板 ABI、函数标签和目标版本目录。

底层接口的定位

run 和字符串形式的 execute 定位等同于外部函数接口或内联汇编：保留是为了不让语言挡住真实需求，但它们不属于常规应用代码。--deny-raw 把这条边界变成可执行的策略，而不是文档里的口头约定。

目标版本兼容依据

  • 随附客户端源码 minecraft_client_26.3-rc-2/version.json 声明数据包版本 major 121、minor 0；生成的 pack.mcmeta 使用 [121, 0] 作为 min_format 与 max_format。
  • 该版本通过注册表 minecraft:function 加载函数；函数目录为 data/<命名空间>/function，标签目录为 data/<命名空间>/tags/function。
  • 计分板除法使用 Mth.floorDiv（向下取整），取模使用 Mth.positiveModulo（结果非负）；除数为 0 时整条命令失败。
  • GiveCommand.MAX_ALLOWED_ITEMSTACKS = 100，数量上限为最大堆叠数乘以 100。
  • 物品数量查询与设置（例如物品过滤的 count）在 26.3 命令树中限制为 1 到 99。
  • 实体生成使用原版 execute summon，返回使用 return 与 execute store result。
