MCLANG 26.3 大语言模型参考 - 中文关键词
===============================================================================
本文件面向需要编写 Mclang（.mcl）源码的大语言模型。目标平台：Minecraft Java
Edition 26.3，数据包 pack format 121.0。本版本正文与示例统一使用中文关键词；
对应的英文关键词版本是 mclang_llm_en.txt。

使用说明
- 第 1-11 节是规范性规则，第 14 节给出可直接使用的完整程序。全部示例都用
  随仓库提供的编译器实际编译过：`mclang check --deny-raw`（其中 12_macros
  与 13_raw 标记为 RAW：它们能正常编译，但会被 --deny-raw 按设计拒绝）。
- 中英关键词完全等价。两个版本由同一份示例翻译而来，编译产物逐字节一致。
- 本文件没有覆盖的场合，优先使用结构化语法，不要改用底层逃生口
  （`原生命令 "..."`、字符串形式的 `执行`）；结构化写法能获得更多编译期检查。

===============================================================================
1 编译器接口
===============================================================================
命令：
  mclang build <源文件.mcl|项目目录> [-o <输出>] [--zip] [--description <文本>] [--deny-raw]
  mclang check <源文件.mcl|项目目录> [--deny-raw]
  mclang lsp
  mclang help | mclang version

- `check` 只检查不写文件，一次返回全部相互独立的诊断；`build` 先做同一套检查，
  通过后才写出数据包。
- 输入可以是单个 .mcl 文件（单模块项目），或以 main.mcl 为入口的目录。
- 默认输出 build/<名字>；`--zip` 写出 build/<名字>.zip；与 `-o` 同用时 `-o`
  就是 zip 文件路径。
- 目录项目可携带 assets/pack.png、assets/pack.mcmeta、assets/overlays/<目录>/
  与 assets/structure/<名字>.nbt，编译器校验后复制进产物。
- `--deny-raw`（严格模式）递归拒绝：`原生命令 "..."`、字符串形式的
  `执行 "..."`、字符串形式的 `返回 原生命令 "..."`、运行期宏调用
  `调用 f 用(...)`，以及声明 `nbt` 参数的宏函数。
- 诊断是中文文本，带源位置，说明实际值与期望值；出现错误时退出码非零。
- 产物可复现：相同源码与参数总是得到相同字节。

2 词法
===============================================================================
注释       // 到行尾，没有块注释。
字符串     "..."，转义 \" \\ \n \r \t，不能跨行。
原始字符串 """...""" 可以跨行，不做转义，适合内嵌 JSON。
数字       32 位范围内的十进制整数；小数如 1.5、0.25。
           NBT 类型后缀紧贴数字：
             b/B 字节、s/S 短整数、i/I 整数、L/l 长整数、f/F 单精度、d/D 双精度
           `1s` 是短整数；`1 s`（带空格）才是时间单位“秒”。
标识符     Unicode 字母/数字/下划线，不能以数字开头。
           ASCII 声明名必须是小写 [a-z0-9_]，不超过 32 个字符，不能是关键词或
           true/false，也不能是 Windows 保留设备名（con、nul、com1、lpt1、
           aux、prn……）。中文等非 ASCII 名字合法：语义检查之后编译器把它们
           换成稳定的随机 8 字母 ASCII 别名，项目内唯一且不冲突。不要预测别名。
关键词     大小写敏感；每个关键词都有中文与英文写法，两种写法都是保留字，可以
           在同一文件里混用。
标点       ; , . .. :: = == != ! && || < <= > >= + - * / %
           += -= *= /= %= -> @ # ~ ^ ( ) { } [ ]
           单独的 `:` 是词法错误；资源位置写在字符串里。
字面量     true / false（中文 真 / 假），只在布尔位置使用。

语句以 `;` 结束。查询、物品、函数标签、进度这几类块式声明，以及独立的
`数据 { ... }` 语句之后，可以再写一个可选分号；带块的目标声明与函数体之后
不能写分号（写了是语法错误）。

===============================================================================
3 项目与模块
===============================================================================
- 目录输入的入口模块固定为 main.mcl，必须写 `命名空间 <名称>;`。整个项目只有
  一个命名空间（小写 ASCII）；其他模块可以省略，写了必须一致。
- 模块路径 = 源文件相对项目根的路径去掉扩展名：lib/math.mcl 与
  lib/math/mod.mcl 都是模块 `lib/math`；入口是空路径。
- 顶层声明默认私有；`公开`（export）之后其他模块才能导入，导入方必须写
  `导入`（import）。
    导入 lib::math;                        // 导入整个模块
    导入 lib::strings::{banner, on_fire};  // 只导入列出的名字
    导入 lib::strings::{banner 作为 wel};  // 导入别名
- 导入路径始终从项目根开始；`导入 main;` 可以导入入口模块，所以导入环合法。
  只有从 main.mcl 可达的模块会被编译。
- 限定名：函数、JSON 资源、进度与函数标签用 `/` 连接模块路径（lib/math/sum
  对应 data/<命名空间>/function/lib/math/sum.mcfunction）；计分变量、目标、
  查询、物品、存储与数据槽用 `.` 连接（lib.state.total）。
- `std::` 保留给内置标准库，项目不能覆盖。
- 直接给单个 .mcl 文件等价于只有入口模块的项目：不需要 main.mcl，也不需要导入。

===============================================================================
4 顶层声明
===============================================================================
一个模块只能包含声明；语句必须写在 `函数` 体内。查询/物品/函数标签/进度与
独立的 数据 语句之后分号可省略；带块的目标声明与函数体之后不能写分号；
命名空间/计分/资源/存储/数据槽 等非块声明必须写 `;`。

4.1 命名空间
    命名空间 <小写 ASCII 名称>;
  整个项目只有一个命名空间，由入口模块声明。

4.2 导入 / 公开
    导入 a::b;                                  // 整个模块
    导入 a::b::{名字, 别的 作为 别名};           // 选择性导入
    公开 函数 ...; 公开 计分 ...; ...            // 暴露声明
  导入的名字在整个模块内可见；局部声明同名时局部优先。两个整模块导入暴露同名
  声明会报错，改用选择性导入或 `作为` 别名。

4.3 计分（全局持久计分变量）
    计分 <名称> = <32 位整数>;
  保存在编译器目标里的假玩家 `#v_<名称>` 上；`/reload` 不会清空，合成的
  __mcl/load 只在缺失时补写初始值。

4.4 目标（用户计分板目标）
    目标 <名称>;
    目标 <名称> {
        准则 = "dummy";                  // 或 trigger、deathCount、health、
                                         // minecraft.custom:minecraft.jump、
                                         // minecraft.mined:minecraft.stone 等
        显示名 = 文本("标签") { ... };    // 文本组件或字符串
        渲染类型 = "integer";             // integer | hearts
        数字格式 = 空白 | 固定(<组件>) | 样式("<JSON 样式对象>");
        显示槽 = "sidebar";               // list|sidebar|below_name|sidebar.team.*
    }
  运行期名称是 `<命名空间>_<名称>`。__mcl/load 负责创建目标并应用显示设置；
  `/reload` 不会清空已有分数。统计准则名称按 26.3 注册表核对。

4.5 查询（可复用实体选择器，本身不生成命令）
    查询 <名称> = 实体("<实体类型或 #标签>") {
        标签("<标签>");                  // 可重复
        排除标签("<标签>");              // 可重复
        排除类型("<id 或 #标签>");       // 可重复，仅用于实体("#标签")
        上限(<正整数>);
        范围(<非负整数>);                // distance=..N
        排序(最近|最远|随机|任意);
        名称("<名字>"); 排除名称("<名字>");
        分数("<目标>", "<区间>");        // 可重复，合并为 scores={...}
        数据(<SNBT 复合>); 排除数据(...);
        坐标盒(<x>, <y>, <z>, <dx>, <dy>, <dz>);
        距离("<区间>");                  // 与 范围 合并
        等级("<区间>");                  // 仅玩家
        游戏模式("survival|creative|adventure|spectator");   // 仅玩家
        队伍("<队伍>"); 排除队伍("<队伍>");
        旋转("<偏航区间>", "<俯仰区间>");
        谓词("<命名空间:id>");
        进度过滤("{命名空间:路径=true/false}");
        物品(内容) { 类型 = "<id|#标签|物品谓词>"; 数量 = <n>; 自定义名称 = "<文本>"; }
    }
  规则：`实体(...)` 已经指定正向类型，所以 `实体类型(...)` 与之矛盾，会被拒绝。
  标签/排除标签/排除类型/分数 可以重复（同一个值重复报错）；其余属性各只能出现
  一次。区间写 `a..b`、`a..`、`..b` 或单个数字；边界倒置或负数（距离、等级）
  报错。凡是需要单个实体的场合（data、xp 查询、传送跟随、store.data、数据槽
  操作、item 命令……）查询必须写 `上限(1)`。`实体("#标签")` 之后只允许原版
  允许的排除类属性。

4.6 物品（带组件的可复用物品堆）
    物品 <名称> = 物品堆("<物品 id>") {
        数量 = <整数，默认 1>;
        自定义名称 = "<文本>";
        物品名称 = "<文本>";
        描述("<文本>");                              // 可重复
        附魔("<附魔 id>", <等级>);                    // 可重复
        存储附魔("<附魔 id>", <等级>);                // 可重复
        损伤 = <整数>;
        最大损伤 = <整数>;
        最大堆叠 = <整数>;
        稀有度 = 普通 | 罕见 | 稀有 | 史诗;
        物品模型 = "<资源位置>";
        染色 = <RGB 整数>;
        附魔光效 = true | false;
        无法破坏 = true | false;
        自定义数据 = 数据 { ... };
        组件 = 数据 { "minecraft:<组件>" = <SNBT>; "!minecraft:<组件>" = {}; };
    }
  `组件` 可补丁任意 26.3 数据组件；`!` 前缀表示删除该组件。组件名按注册表核对，
  重复设置或与具名属性冲突会报错。`自定义数据` 写入 minecraft:custom_data
  组件。`最大堆叠` 大于 1 时不能再声明 `最大损伤`。give 数量必须在
  1..最大堆叠*100（默认最大堆叠为 1）之间。

4.7 存储（供 自身.保存物品/恢复物品 使用的物品列表位置）
    存储 <名称> = 物品列表("<存储资源位置>", "<NBT 路径>");
  __mcl/load 在缺失时把路径初始化成空列表；`/reload` 不会清空已有内容。

4.8 数据槽（供 自身.存入/取出/移除数据 使用的命名 NBT 位置）
    数据槽 <名称> = 物品数据("<路径>");     // Item.components."minecraft:custom_data".<路径>
    数据槽 <名称> = 实体数据("<路径>");     // 实体上的 data.<路径>
  路径由点分键组成，可带 [下标] 与引号键，例如 pc_items、pc_note.name、
  records[0].payload。物品数据槽只能配合 minecraft:item 查询使用；实体数据槽
  不能指向玩家。

4.9 资源（原样 JSON 资源）
    资源 <类型> <名称> = """<JSON>""";
  类型是 26.3 资源注册表里的目录名（见 10.9），例如 predicate、recipe、
  loot_table、damage_type、"tags/block"、"worldgen/feature"；`配方`/`谓词`/
  `对话框` 是前三个的中文写法。名称可写标识符或字符串。JSON 在编译期解析；
  谓词内联对象必须有已注册的 `type`；配方与战利品表池有部分 schema 检查。
  输出路径 data/<命名空间>/<类型>/<名称>.json。

4.10 进度（数据包唯一的事件入口）
    进度 <名称> {
        父进度 = <已声明进度> | "<外部 id>";              // 可选
        准则 <准则名> {
            触发器 = <26.3 CriteriaTriggers 名称>;         // 可省略 minecraft:
            条件 = """<触发器条件 JSON>""";                // 可选
        }                                                 // 至少一条准则
        要求 = 全部 | 任意;                                // 默认 全部
        奖励 {
            函数 = <已声明函数> | "<外部 id>";
            经验 = <整数>;                                 // 默认 0
            战利品 = <已声明战利品表> | "<外部>";           // 可重复
            配方 = <已声明配方> | "<外部>";                 // 可重复
        }
        展示 {
            图标 = <已声明物品>;                           // 展示块内必填
            标题 = "<文本>"; 描述 = "<文本>";              // 展示块内必填
            框架 = 任务 | 目标 | 挑战;                      // 默认 任务
            背景 = "<纹理资源位置>";   // 根进度必填；有父进度的进度禁止声明
            显示提示 = true; 聊天公告 = true; 隐藏 = false;
        }
    }
  进度完成一次后不再触发；需要重复响应时在奖励函数里调用
  `进度.撤销(自身, <进度>)`。要求=全部 会为每条准则生成一个单元素组（AND），
  要求=任意 生成一个包含全部准则名的组（OR）。
  `条件` 保持原版 JSON；已知触发器的条件字段按 26.3 快照核对。内联条件的
  `type` 必须是 26.3 注册的 loot condition（可省略 minecraft:，写错会给出
  候选）；all_of/any_of 的 terms、inverted 的 term 递归校验；victims、items、
  ingredients 这些 listOf() 字段只接受数组。26.3 的内联
  战利品条件用 `type` 作判别键，例如方块匹配：
    {"location":{"type":"minecraft:match_block","blocks":"minecraft:dirt"}}
  实体谓词要套一层：
    {"entity":{"type":"minecraft:entity_properties","entity":"this",
               "predicate":{"minecraft:entity_type":"minecraft:zombie"}}}

4.11 函数标签
    函数标签 <名称> {
        值(<已声明函数>);
        值(#<已声明标签>);
        值("<外部函数 id>");
        值("#<外部标签 id>");
        替换 = true | false;              // 默认 false
    }
  输出到 data/<命名空间>/tags/function/<名称>.json。本地引用检查存在性与循环；
  `调用 #标签()` 会展开全部成员并检查它们的参数与上下文要求。

4.12 函数
    [@加载|@每刻|@实体|@玩家|@非玩家] 函数 <名称>(<参数>, ...) [-> 计分] { ... }
    [同样属性] 宏 函数 <名称>(<类型> <宏参数>, ...) { ... }
  属性（分组互斥）：
    @加载  加载与 /reload 时运行。不能带参数、不能有返回值。
    @每刻  每游戏刻运行。不能带参数、不能有返回值。
    @实体  要求任意实体上下文。
    @非玩家 要求确定的非玩家实体上下文。
    @玩家  要求玩家上下文。
    @加载/@每刻 不能与实体属性组合。
  普通参数保存在私有假玩家 `#p_<哈希>` 上；调用方先写值再 `function
  <命名空间>:<函数>`。因此原版直接调用或 `调度` 参数化函数会读到上次残留值，
  编译期直接拒绝这类调用。参数名不能与全局计分变量重名（后者始终存在）。
  带 `-> 计分` 的函数必须以显式 `返回` 结束。
  宏参数类型：整数、小数、文本、资源、数据（integer/decimal/text/resource/
  nbt）。文本与 NBT 字符串里可以写 `$(名称)` 占位符；坐标分量可以写
  `宏(名称)`。宏参数不是计分变量，不能与普通参数混用。宏函数不能是
  @加载/@每刻，也不能声明返回值。

===============================================================================
5 语句
===============================================================================
除非以 `}` 块结束，每条语句都要写 `;`。

5.1 赋值与局部变量
    令 <名称> = <表达式>;          // 词法局部变量，块作用域
    <名称> = <表达式>;             // 全局计分值或局部变量
    <名称> += <表达式>;  -=  *=  /=  %=
  局部变量不能遮蔽全局计分变量或参数。右操作数是常量 0 的除法/取模直接报错。
  局部变量存放在 `#l_<哈希>` 槽位。

5.2 控制流
    如果 <条件> { ... } 否则 { ... }
    当 <条件> { ... }
    对于 <名称> 在 <起点>..<终点> { ... }
    跳出;      跳过;
  - 编译期可确定的条件会被折叠：`如果 1 == 1` 直接内联真分支，`如果 2 < 1`
    整段消失，`当 0 == 1` 不生成任何命令。
  - 连续嵌套的 如果 合并成同一条原版条件链（`执行 如果 … 如果 …`），同一条链里
    已成立的条件不再判断（`如果 a && a`、`如果 x > 10 { 如果 x > 5 … }`）；
    矛盾组合（`如果 x > 10 { 如果 x < 5 … }`）整段不生成命令。含 function/
    predicate 等有副作用的条件保留原求值路径。
  - `&&` 与 `||` 从左到右短路；左侧始终按源码求值，右侧即使恒真也不会删掉
    左侧调用。`&&` 右侧是比较时不单独分配标志计分项。
  - 比较生成的范围与原版一致：`x < c` → `matches ..c-1`、`x > c` → `matches
    c+1..`、`x == c` → `matches c`、`x != c` → `unless … matches c`；字面量
    始终在 i32 内（越界的 `x < -2147483648`、`x > 2147483647` 不生成判定）。
  - `对于` 是半开区间 [起点, 终点)；终点表达式只求值一次（动态终点存入临时
    计分项）。常量空区间不生成命令。跳出/跳过 只作用于最内层 对于/当，在
    遍历/召唤 块里会被拒绝。
  - `返回` 只能直接出现在函数最外层代码块。如果/当/对于/遍历/召唤/执行/
    在维度 都会下降为辅助函数，块里的 返回 只会结束辅助函数。需要条件结果时
    先给局部变量赋值，在函数末尾统一返回。

5.3 实体块
    遍历(<查询>) { ... }
      对查询命中的每个实体执行一次，@s 指向该实体；玩家查询进入玩家上下文，
      其他查询进入非玩家实体上下文。
    召唤("<实体类型>"[, <坐标|精确坐标>]) { ... }
      在当前或指定位置召唤实体，块内以新实体为 @s，始终是非玩家上下文。
      minecraft:player 与 minecraft:fishing_bobber 不可召唤。
    在维度("<维度 id>") { ... }
      块内语句在指定维度执行，执行实体不变。

5.4 结构化执行
    执行 [<修饰符>...] [如果 <条件> | 除非 <条件>]... [<存值>...] { ... }
  子句顺序固定：修饰符 -> 条件 -> 存值。修饰符重复、条件写在修饰符之前、
  存值写在条件之前都会报错。
  修饰符：
    作为(<查询>)              以查询命中的每个实体为执行实体
    在(<查询>)                在查询命中的每个实体处执行，但不改变执行实体
    定位于(<坐标|精确坐标>)     设置位置并把锚点重置为脚部
    转向(朝向(偏航, 俯仰))
    面向(坐标(<x>,<y>,<z>)) | 面向(实体(<查询>), 眼睛|脚)
    对齐(x|y|z 的子集，例如 xz)   把执行位置对齐到方块
    锚点(眼睛|脚)
    进入维度("<维度>")
    关系(<关系>)              关系：主人|拴绳者|攻击目标|攻击者|载具|控制者|起源|乘客
    召唤实体("<实体类型>")     召唤并以新实体继续执行
  条件复用整套条件语法（第 6 节），从左到右短路。存值捕获块内最后一条命令：
    存值.结果(<持有者>, <目标>)              命令结果（整数）
    存值.成功(<持有者>, <目标>)              成功为 1，否则 0
    存值.结果(Boss栏, "<id>", 值|上限)
    存值.成功(Boss栏, "<id>", 值|上限)
    存值.数据([结果|成功,] <来源>, "<路径>", 字节|短整数|整数|长整数|浮点|双精度[, 缩放])
      <来源> 是 实体,<持有者> | 方块,<坐标> | 存储,"<id>"
  存值规则：
  - 块内最后一条语句必须是普通命令、赋值、计分板设置或调用带 `-> 计分` 的
    函数；以 如果/当/遍历/召唤/执行 结尾会被拒绝。
  - 条件不成立时块体不运行，什么都不会写入。
  - <持有者> 支持 自身、投掷者 或查询（查询选择器可以一次写多个实体）。
    投掷者目标先捕获到临时计分项再用 `关系(起源)` 复制，未命中时目标保持原样。
  - 存值.数据的实体来源要求 上限(1)；自身 要求非玩家上下文。

5.5 函数调用与调度
    调用 <函数>(<实参>...);     |  <函数>(<实参>...);      // 可省略 调用
    调用 #<函数标签>();         |  调用 "<外部:函数>"();
    令 <名称> = <函数>(<实参>...);        // 仅限带 -> 计分 的函数
    调度 <函数>() 延后 <数字> 刻|秒|天 [追加|替换];
    调度 #<函数标签>() 延后 <数字> 刻|秒|天 [追加|替换];
    调度.清除(<函数>);
  实参从左到右求值写入参数槽，然后执行 `function <命名空间>:<名称>`。参数个数、
  类型与上下文要求都会被检查。标签不能传参，因此被调用标签的每个成员都必须
  无参数。`调度` 发生在未来的游戏刻、不保留实体上下文，所以目标函数必须无参数、
  无上下文属性；模式默认 替换。调度.清除 只接受函数，不接受标签。时间换算与
  原版一致：20 刻 = 1 秒，24000 刻 = 1 天。

  字段直接写在 `type` 旁边（没有旧式 config 包裹层）。

5.16 返回与底层逃生口
    返回;                                  // 无返回值函数 -> `return 0`
    返回 <表达式>;                          // 带 -> 计分 的函数，仅限最外层
    返回 失败;

    返回 原生命令 "<原生命令>";              // RAW
    原生命令 "<原生命令>";                   // RAW
    执行 "<子句>" { ... }                    // RAW，只能写子句，不能含 run

6.1 表达式（都产生 32 位计分值）
    <整数>                                  32 位常量，编译期折叠
    <名称>                                  全局计分值、参数或局部变量
    <函数>(<实参>...)                       调用带 -> 计分 的函数
    计分板.取(<持有者>, <目标>)
    经验.查询(<上限(1) 玩家查询>, 点数|等级)
    秒表.查询("<id>"[, <缩放>])
    时间.查询(["<世界时钟>"]); 时间.查询游戏时间()
    游戏规则.查询("<规则>"); 世界边界.获取(); 难度()
    Boss栏.取("<id>", 值|最大值|可见|玩家列表)
    计数(<查询>)                            命中实体数量
    随机(<下界>, <上界>)                    闭区间随机整数（无序列）
    数据操作.取(<来源>, "<路径>"[, <缩放>])
    计算(<默认|方块,<坐标>|实体,<持有者>>, float|integer, "<provider>"[, <缩放>])
    <返回整数的扩展命令>                     例如 标签.列出(...)、实体属性.取(...)
  运算符：一元 `-`；二元 `+ - * / %`；括号。`* / %` 高于 `+ -`，同级从左到右。
  纯常量表达式会折叠；常量除以 0 或超出 i32 范围直接报错。运行期运算沿用原版
  计分板 32 位语义与 floorDiv/floorMod：-3 / 2 == -2，-3 % 2 == 1，
  3 % -2 == -1。

6.2 条件
    <表达式> == <表达式>    !=    <    <=    >    >=
    !<条件>   <条件> && <条件>   <条件> || <条件>
    ( <条件> )
    谓词(<已声明谓词资源>)
    方块(<方块坐标>, <方块状态或 #标签>)
    区域方块(<起点>, <终点>, <目标>[, 全部|遮罩])
    生物群系(<方块坐标>, "<生物群系或 #标签>")
    已加载(<方块坐标>)
    维度("<维度 id>")
    实体(<查询>)                          查询命中时为真
    数据(实体, <持有者>|方块, <坐标>|存储, "<id>", "<路径>")
    物品条件(实体, <持有者>|方块, <坐标>, "<槽位>", <物品谓词>)
    槽位条件(实体, <持有者>|方块, <坐标>, "<槽位>")
    函数条件(<已声明函数或 #标签>)
    秒表("<id>")
  物品谓词参数写法：
    "<物品 id>" | "#<物品标签>" | 物品谓词("*"|"<id>"|"#<标签>") {
        存在("<组件>");
        !存在("<组件>") || 等于("<组件>", <SNBT>);
        匹配("<组件>", 数据 { ... });                    // 组件子谓词
        匹配("minecraft:count", 数据 { min = 1; max = 64; });
    }
  以 `;` 分隔的子句之间是 AND；子句内的 `||` 是备选条件的 OR；`!` 取反单个
  测试。`minecraft:count` 是原版提供的数量伪组件。
  求值：`&&`/`||` 从左到右短路。条件在当前执行上下文里求值。实体/方块/物品/
  数据 查询失败时条件为假（表达式读取失败为 0），取反保持这个边界：
  `!数据(实体, q, "Health")` 在 q 没有命中时为真。
  计分值比常量生成原版 `matches` 范围（闭区间）：`x < c` → `..c-1`、`x > c` →
  `c+1..`、`x == c` → `c`、`x != c` → `unless … matches c`；字面量始终在 i32 内，
  不可能成立的条件不生成判定。

7 执行上下文
===============================================================================
上下文关系（能力不向下继承）：
    无（@加载 / @每刻）
      实体（@实体）
        非玩家（@非玩家、非玩家查询的 遍历/召唤）
        玩家（@玩家、玩家查询的 遍历、玩家上下文）
  无     ：没有 @s，只能执行与上下文无关的命令。
  实体   ：任意实体，可能是玩家。
  非玩家 ：确定不是玩家；写实体 NBT 必须处于这里（数据操作、数据合并、
           自身.设置无敌/设置无视重力、保存/恢复/存入/取出/移除数据/
           清空物品、存值.数据 的 自身）。
  玩家   ：确定是玩家；消息.自身、自身.给予物品、经验、清除()/给予(自身,...)、
           屏幕标题/Boss栏/对话框 使用 自身 时，以及 触发，都必须在这里。
  数据包不能写玩家数据；对玩家 NBT 的写入会被 Minecraft 与编译器同时拒绝。
上下文来源：函数属性；遍历(查询)（玩家查询 -> 玩家，其他 -> 非玩家）；
召唤 块（非玩家）；执行 的 作为/在/关系/召唤实体 按原版规则改变。定位于/
转向/面向/进入维度 不改变 @s。

8 内置标准库
===============================================================================
显式导入：`导入 std::math::{abs};` 等。只有可达模块会被编译；导入一个模块会
生成它的全部公开函数。`std::` 保留。所有值都是 32 位计分值；布尔函数返回
0 或 1（0 为假，其他为真）。时间函数按每秒 20 刻换算。函数名与模块名是 API
标识符，不随关键词切换。
  std::math   abs(x)、min(a,b)、max(a,b)、clamp(x,lo,hi)、sign(x)
  std::state  normalize(x)、toggle(x)、latch(previous, signal)、
              rising_edge(previous, current)、falling_edge(previous, current)
  std::time   seconds_to_ticks(s)、ticks_to_seconds(t)、
              interval_due(now_tick, last_tick, period)、
              cooldown_ready(now_tick, deadline_tick)、
              remaining(now_tick, deadline_tick)
  std::random chance(0..100)、chance_per_mille(0..1000)
  interval_due 的周期必须严格大于 0，调用方在触发后更新 last_tick；
  cooldown_ready 在到达截止刻及之后为真；remaining 返回剩余刻数，过期后为 0；
  概率参数超出范围时退化为必然结果。rising_edge/falling_edge 需要调用方保存
  上一刻的值；clamp 在下界高于上界时返回下界。

11 硬性规则与陷阱
===============================================================================
以下每条都由编译器强制；写代码时逐条对照。
 1. `返回` 只能直接出现在函数最外层。不能在 如果/当/对于/遍历/召唤/执行/
    在维度 块里使用。需要条件返回值时先给局部变量赋值，在末尾统一返回。
 2. 带参数的函数只能从 Mclang 代码调用：语句/表达式里的普通调用或字面量宏
    调用。参数保存在共享假玩家上、由调用方先写值，所以不能 `调度`，也不能被
    原版 /function 直接调用。
 3. `调度` 的目标必须无参数、无上下文要求；目标是函数标签时每个成员都要满足。
    调度.清除 只接受函数。
 4. 所有需要单实体的参数都要求查询带 `上限(1)`；编译器不会悄悄挑“第一个”。
 5. 数据/NBT 写入需要确定的非玩家上下文。玩家 NBT 只读。
 6. 消息.自身、自身.给予物品、经验、清除()/给予(自身,...)、触发 需要确定的
    玩家上下文。
 7. `执行` 的存值块不能以控制结构结尾，否则捕获值没有明确定义。
 8. `--deny-raw` 拒绝 原生命令 "..." / 执行 "..." / 返回 原生命令 "..." /
    运行期 `用` 宏调用 / `数据` 宏参数。优先用结构化写法保持严格模式干净。
 9. 声明名不能是关键词（中英都算）或 true/false；ASCII 名必须小写、不超过
    32 字符、不能是 Windows 保留设备名。
10. 中文（非 ASCII）声明名会被换成稳定的随机 ASCII 别名；诊断仍显示源码名。
    不要写依赖生成别名的代码。
11. 整个项目共用一个命名空间；每个模块要么省略 `命名空间`，要么写相同的值。
12. 常量折叠不会删除副作用：`副作用() == 1 && 0 == 1` 仍会调用一次 副作用()；
    如果/否则 的条件只求值一次。
13. `对于` 是半开区间，终点只求值一次。`当` 每轮重算条件，可能撞上命令链
    上限；请确保循环体改变条件或包含 跳出。
14. 跳出/跳过 只跳出最内层 对于/当；在 遍历/召唤 块里会被拒绝（每个实体在
    自己的辅助函数里执行）。
15. `/reload` 不会重置计分板、存储或秒表；一次性创建用计分标志守护。
16. 表达式查询失败读作 0；条件查询失败为假。失败查询取反为真。
17. give 数量必须在 1..最大堆叠*100 之间；物品.替换/填充/覆盖 数量 1..99。
    物品定义默认数量 1、默认最大堆叠 1。
18. 带 `-> 计分` 的函数必须以 `返回` 结束；无返回值函数可以只写 `返回;`。
    `返回 失败` 不产生值。
19. `数据 { ... }` 合并到 @s。方块实体数据写在 设置方块/填充 的 数据 参数里。
    自定义数据 的键是用户数据，不做别名替换。
20. 单条生成函数行不能超过 2,000,000 个 UTF-16 单元；避免超大的常量填充。
21. 消息参数（广播/动作消息/私聊/队伍消息）是单行字符串，UTF-16 长度不超过
    256；这些位置拒绝带 `[...]` 的选择器。
22. 文本组件里 解释 与 纯文本 不能同时为真；回退 只用于 对象内容；
    解释/纯文本/分隔符 只用于 数据 组件。
23. 进度展示规则：根进度必须有 `背景`，带 `父进度` 的进度禁止声明 `背景`；
    图标 必须是已声明物品。
24. 进度完成一次后不再触发；可重复事件在奖励函数里撤销。
25. 资源 JSON 会解析并做部分 schema 检查，但完整 codec 仍由 Minecraft 在加载
    时验收。只有 `谓词` 声明能在条件里引用。
26. `max_minecart_speed` 会被拒绝（实验特性默认未启用）。
27. 名称与取值按 26.3 快照核对；不要凭记忆猜注册表名、方块状态属性或实体
    NBT 键。
28. 区块与数据的访问时机无法静态检查：已加载()、查询、数据读取在运行期都可能
    失败；按 0/假 设计逻辑。

--- 02_core.mcl：声明、控制流、函数、返回值、调度、函数标签 ---

函数 load() {
    消息.全部("core demo loaded", 绿色);
}

@每刻
函数 tick() {
    counter += 1;
    如果 counter >= 20 {
        counter = 0;
        total = compute_sum(10);
        如果 total > 100 {
            调用 #batch();
        }
    }
}

函数 compute_sum(bound) -> 计分 {
    令 result = 0;
    对于 index 在 1..bound {
        如果 index % 2 == 0 {
            跳过;
        }
        如果 index >= 8 {
            跳出;
        }
        result += index;
    }
    当 active < 3 {
        active += 1;
    }
    如果 result > 10 && active == 3 {
        result -= 1;
    } 否则 {
        result += 1;
    }
    返回 result;
}

函数 reset() {
    counter = 0;
    total = 0;
    active = 1;
}

函数 later() {
    调度 later() 延后 1.5 秒 追加;
}

函数 queue() {
    调度 cleanup() 延后 2 天 替换;
    调度.清除(cleanup);
}

    值(reset);
    值(#announcement);
}

    值(cleanup);
}
